# 图像关键点可见性与遮挡标注规则

本资料覆盖 BHZD 平台人体姿态估计、动物姿态、面部关键点任务的可见性与遮挡标注。读者对象是关键点标注员、质检工程师、教学管理员。

## 关键点标注：核心定义

关键点标注由有序坐标数组 `[(x1,y1,v1), (x2,y2,v2), ...]` 构成。`vi` 为可见性标志位，常用 0=未标注、1=标注但被遮挡、2=完全可见。

不同框架对可见性位定义略有差异。本项目使用 0/1/2 三级可见性，最终评测会按各框架适配映射。

## 关键点标注：可见性判定

- 可见性 2：关键点可看到且可精确定位（如肘部可见）。
- 可见性 1：关键点存在但被遮挡或不确定（如猜测的左膝位置）。
- 可见性 0：关键点完全离开图像或不可识别。
- 边界争议：宁可标 1 也不要标 0；评测时 `v=1` 的关键点会按"不确定"对待。

`v=1` 时仍需提供 `(x, y)` 坐标，因为这是后续半监督训练的伪标签。

## 关键点标注：遮挡截断区分

- 关键点被遮挡但能合理推断位置 → `v=1`。
- 关键点因人物离开图像而不可见 → `v=0`，坐标用估算值或 `(0, 0)` 占位。
- 关键点被自身或他人完全遮蔽（如手插口袋）→ `v=1`。
- 关键点被光照/模糊导致不可见 → `v=0`，不要猜测。

遮挡与截断不混用同一字段。

## 关键点标注：多人场景

多人场景下：

- 每个关键点带 `instance_id`，不同人之间不共享关键点。
- 同一人关键点按题目要求的顺序存储（COCO 17 点 / OpenPose 18 点 / 自定义）。
- 多人重叠时遮挡字段独立记录，不混合 `instance_id`。
- 中心点未必 `v=2`，应按可见性记录。

## 关键点标注：标签融合与互转

- COCO 17 点与 OpenPose 18 点有 1 点错位，标注员必须按题项规定版本标注，不要混合。
- 自定义关键点（如医学关键点）应在 `keypoint_definitions.json` 中显式声明顺序。
- 不同框架的关键点融合应通过 `keypoint_mapping` 字段完成，不要在前端硬编码。

## 关键点标注：常见误区

- 遮挡关键点直接标 0，导致后续训练丧失半监督信号。
- 多人关键点合并到同一 `instance_id`，丢失实例区分。
- 使用其它数据集的关键点定义，错位严重。
- 把关键点坐标写小数导致与坐标系统对齐失败。

## 关键点标注：示例与反例

正例（虚构示例）：行人站姿，左肘可见 2，左膝因大腿外侧遮挡标 1 并写估算坐标 `(165, 240)`。

反例：所有关键点都标 2，无法区分真正可见与估计位置，训练时模型学不到可见性含义。
