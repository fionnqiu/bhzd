# 文本分类中意图模糊样本的判断与处理流程

本资料围绕 BHZD 平台文本分类任务中常见的"意图模糊样本"问题，给出识别条件、判断步骤、回退策略与记录要求。读者对象是标注员、质检工程师与教学管理员，适用于教学型短文本分类、企业客服工单分类、政策问答分类等场景。

## 意图模糊样本：核心定义

意图模糊样本指同时满足以下条件的文本：

- 文本内容可以在两个或两个以上的合法类别下被合理支持。
- 任一可选类别在标签词表说明中都没有被排除。
- 文本未提供足够上下文判断唯一意图。

这类样本不是标注错误，而是任务定义边界或词表覆盖不足的表现。

## 意图模糊样本：识别条件

识别时应同时满足下列条件：

- 文本长度过短，例如 ≤ 5 个中文 token 或单句结构。
- 缺少主题词、地点、时间等可锚定类别的线索。
- 标签词表中确实存在两个以上候选类别，且语义覆盖合理。
- 不属于内容违规或敏感词命中（此类应转人工审核而非标注为模糊）。

单一条件不构成"模糊"。例如长文本里同时给出两条意图线索时，仍可能由上下文排除其中之一，不应直接判为模糊。

## 意图模糊样本：处理步骤

推荐的人工处理流程：

1. 标注员先按词表定义判断主意图与备选意图，分别记录在 `primary_label` 与 `candidate_label`。
2. 若主意图与备选意图置信度接近，则把样本标记为 `ambiguous`，并填写 `ambiguity_reason`（简短描述），不要强行二选一。
3. 若样本可以被更高层级的元数据（用户分群、会话上文）解决，标注员应改为引用元数据并重新判断，而不是在原始文本上猜测。
4. 若词表无法覆盖，应上报"词表缺失"工单，由教学管理员决定是否新增类别，而不是私自归到任意现有类别。

任何模糊样本不得直接删除或随机分配，必须留下处理记录。

## 意图模糊样本：回退与上传策略

上游 RAG 调用或练习题评估遇到模糊样本时：

- 单一意图得分阈值低于 0.6 时，将样本纳入"模糊池"由质检复核。
- 模糊样本的占比超过该批 10% 时，应暂停自动入库，回到词表修订流程。
- 模糊样本不得作为正面或负面训练样本直接喂入模型，避免放大争议。
- 在教学场景中，模糊样本可作为"边界题"用于学员练习，并附明确标签词表说明。

## 意图模糊样本：示例与反例

正例（虚构示例）：用户发送"在哪里取号？"。候选类别为 `排队指引`、`门诊导航`、`取药咨询`。文本未给出医院或场景，无法确定。标注员填 `primary=排队指引`、`candidate=门诊导航`，标记 `ambiguous=true`，并在 `ambiguity_reason` 中写"缺少场景上下文"。

反例：标注员看到"在哪里取号？"直接归到 `门诊导航`，并填写 `notes: 看起来像位置问询`。该处理丢掉了模糊信息，导致后续训练数据中的边界冲突无法追溯。

## 意图模糊样本：常见误区

- 把模糊样本全部归为低频类别以"看起来合理"。
- 用模型预测代替人工判断，导致长尾类别的样本被掩盖。
- 用"先入为主"的客户画像反推文本意图，引入标签泄漏。
- 未记录 `ambiguity_reason`，事后无法复核。
