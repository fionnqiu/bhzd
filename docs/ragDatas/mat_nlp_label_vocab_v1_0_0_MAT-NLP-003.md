# 文本分类标签词表的版本管理、覆盖度检查与冲突解决

本资料解决 BHZD 平台文本分类标签词表（label vocabulary）的版本边界、覆盖度检查和冲突解决方法。读者对象是教学管理员、词表编辑者与质检工程师。

## 标签词表：核心定义

标签词表是文本分类任务使用的有限集合 `L = {l1, l2, ..., ln}`，每个标签 `li` 必须有唯一的标签编码、显示名、操作定义、互斥关系与适用范围。互斥关系指同一时间同一文本只能被分配到 `L` 中的某一个标签；多标签任务应单独建表而不是混合。

词表是任务的核心契约。RAG 资料和练习题都引用这份契约，因此它的变化必须可追溯。

## 标签词表：版本管理

- 使用 `v主.次.修订` 三段式版本号：主版本号变化代表类别边界调整或新增删除语义层；次版本号代表新增类别；修订版本号代表措辞或示例修正。
- 每次发布必须记录 `version`、`effective_at`、`author`、`reviewer`、`deprecation_of` 等字段；旧版本归档至 `docs/ragData/_archive/materials/<词表ID>/<版本>/`。
- 同一任务对应一份当前生效词表；旧版本只用于历史样本回溯，不进入新标注流程。
- 任何引用旧词表的练习题、参考资料与 RAG 切片必须在审核完成后统一更新或显式弃用。

## 标签词表：覆盖度检查

新词表投入标注前，必须完成覆盖度检查：

- 抽样不少于 200 条历史样本（不足则取累计样本），对每条判断是否存在至少一个候选标签。
- 覆盖率 = 命中样本数 / 总样本数。低于 95% 的词表必须返工。
- 对未命中的样本，分析原因属于"词表覆盖不足"还是"样本本身无效"。前者应新增标签；后者应过滤而不是扩展词表。
- 标签覆盖分布检查：每个标签至少 5% 样本（按数量）。若不足，应考虑是否合并或拆分标签。

覆盖度检查会输出"覆盖样本清单"和"未命中原因分类"，作为词表评审的证据。

## 标签词表：冲突解决

两个或多个标签可能对同一样本给出合理分配，称为词表冲突。冲突处理规则：

1. 优先级最低的层是"标注员个人习惯"。先复核词表定义是否清晰。
2. 若词表定义清晰仍冲突，构造"边界例句库"并扩大定义说明。
3. 若仍无法消除冲突，引入互斥组（mutex groups），例如"咨询类 vs 投诉类"互斥。
4. 互斥仍未覆盖，则上报至版本变更评审，纳入下一个版本调整。

每次冲突处理必须有记录，包括样本 ID、争议标签、决定理由和处理人。

## 标签词表：示例与反例

正例（虚构示例）：某客服场景词表新增"投诉升级"，覆盖旧标签"投诉"。主版本号提升，标注员对历史投诉类样本重新分配，新词表与旧词表的映射记录在迁移说明中。

反例：直接在聊天群里口头变更词表，没有写入词表文件也不更新版本号。三天后标注员 A 和 B 对同一个样本给出不同标签，质检找不到依据决定接受谁的判断。
