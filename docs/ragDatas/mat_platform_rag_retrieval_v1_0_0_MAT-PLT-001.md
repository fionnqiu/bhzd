# RAG 检索验收流程与三道必测问题设计

本资料介绍 BHZD 平台 RAG 资料入库前的检索验收流程与三道必测问题设计方法。读者对象是 RAG 质检员、教学管理员。

## 检索验收：核心定义

检索验收（retrieval acceptance）是在资料发布前用冻结的检索参数与典型查询检验召回质量的流程。每个资料主题至少设置 3 道必测问题，全部通过才允许入库。

未通过检索验收的资料不得进入活跃语料，必须退回修改。

## 检索验收：冻结参数

默认冻结参数（除非单独说明）：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 嵌入模型 | 项目基线模型 | 关闭多模型对比 |
| top_k | 5 | 检索返回 5 个片段 |
| score_threshold | 0.35 | 余弦相似度阈值 |
| 混合检索 | 开启 | 向量 + 关键词 |
| 重排 | 关闭 | 不开 reranker |
| 温度参数 | 不适用 | 检索阶段无温度 |

参数变更必须留下变更日志与新基准。

## 检索验收：必测问题设计

每个主题必须设计 3 道问题：

1. 直接定义或事实问题：例如"宏平均 F1 的定义是什么"。
2. 带条件的操作问题：例如"在类别不平衡时，宏平均 F1 适用条件是什么"。
3. 反例或误区问题：例如"宏平均 F1 不能用什么场景"。

存在被替代版本时，每个主题还需增加 1 道版本辨别问题。

## 检索验收：无答案问题

每个批次需另准备 `max(3, ceil(批次资料数 ÷ 20))` 个无答案问题：

- 问题落在本批次的主要领域，但本批次资料不能提供直接答案。
- 预期结果：相关材料不越过 0.35 阈值，启用回答生成时执行拒答策略。
- 全部无答案问题通过才允许批次发布。

无答案问题防止"模糊答非所问"被误判为权威答案。

## 检索验收：通过条件

每道必测问题必须满足：

- 预期当前版本资料切片进入返回的前 5 个结果。
- 命中切片同时包含回答所需的核心结论与限制条件。
- 不出现相似但错误的旧版本压过当前版本。
- 不被资料中的模糊语句误导为确定答案。

任一问题失败，对应资料退回修订而非批次整体否决。

## 检索验收：常见误区

- 把测试问题写得过于简单，无法暴露边界条件。
- 用未冻结参数重复测试，结果不可重现。
- 把无答案问题直接列入测试集而不分离，导致 batch 重复失败。
- 忽略旧版本辨别问题，发布后被旧版本压过。

## 检索验收：示例与反例

正例（虚构示例）：3 道必测 + 1 道版本辨别 + 3 道无答案，全部通过，材料 v1.0.0 发布。

反例：未设计版本辨别问题，旧版本 v0.9.0 仍在召回结果中靠前，误导用户。
