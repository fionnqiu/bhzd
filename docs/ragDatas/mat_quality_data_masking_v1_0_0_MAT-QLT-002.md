# 标注数据的脱敏规则与可识别风险控制

本资料覆盖 BHZD 平台标注数据的脱敏要求、可识别风险与分级处理。读者对象是数据治理员、质检工程师、教学管理员。

## 标注脱敏：核心定义

脱敏（data masking）指通过删除、替换、变形等手段，使原始信息在不损失业务关键性的前提下不可识别个人或组织。

脱敏不等于简单替换部分字符；优先删除非必要字段，仅在必须保留结构时使用明显虚构或不可逆置换。

## 标注脱敏：识别信息分类

按敏感等级分类：

| 等级 | 类型 | 示例 | 处理建议 |
| --- | --- | --- | --- |
| L0 必要 | 显式业务字段 | 订单 ID、任务 ID | 保留 |
| L1 一般 | 直接标识 | 姓名、手机号、身份证 | 删除或置换 |
| L2 敏感 | 关联可识别 | 地址、单位、邮箱 | 删除或聚合 |
| L3 高度敏感 | 密码、令牌、密钥 | API Key、连接串 | 必须删除 |
| L4 推断可识别 | 间接组合 | 多条记录组合反推 | 删除字段或样本 |

L1 至 L4 必须在发布前完成脱敏或删除。

## 标注脱敏：脱敏技术

可用技术包括：

- 删除：直接移除字段，损失不可恢复。
- 替换：用明显虚构值替换，例 `user@example.test`、`13800000000`。
- 散列：用单向散列函数将字段映到固定长度的不可逆字符串。
- 置换：保持字段格式但替换为虚构数据，如 `张三`、`XX 公司`。
- 聚合：用统计量或类别替代精确值，如 `age_bucket=30-39`。

技术选择按业务需求。L1 中"姓名"建议删除或置换；"身份证号"必须删除或采用不可逆置换。

## 标注脱敏：发布前再识别评估

脱敏后须做再识别评估：

- 用姓名、单位、生日三字段组合尝试识别具体个人。
- 用电话、地址、邮箱组合做同样评估。
- 用主语、动词、宾语组合评估是否存在唯一身份。
- 用同一作者多段文本合并评估语义指纹。
- 用任务上下文 + 时间戳 + 设备 ID 评估用户行为重建。

任一评估命中具体身份，重新脱敏。

## 标注脱敏：常见误区

- 只对身份证号脱敏，忽略邮箱、单位等可推断字段。
- 用 `***` 部分替换，仍可被推断还原。
- 用真实姓名作为标注员 ID（如 `lisi@bhzd.local`），违反内部脱敏。
- 保留截图或照片中的身份证、人脸等敏感信息。
- 内部说明文档中保留原始敏感值。

## 标注脱敏：示例与反例

正例（虚构示例）：客户反馈文本"我今天去 XX 医院拿药"。替换为"我今天去 XX 医院拿药"或保留但删除医院具体名称与人名。

反例：原样保留"我今天去中心医院拿药，李医生给我看了"，包含可推断信息。
