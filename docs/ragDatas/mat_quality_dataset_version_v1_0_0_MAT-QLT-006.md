# 标注数据集版本号与变更日志规范

本资料覆盖 BHZD 平台标注数据集的版本号格式、变更日志要求、发布与回滚流程。读者对象是数据治理员、标注管理员、教学管理员。

## 数据集版本号：核心定义

版本号用于标记数据集某次发布的事实标识符。它不只描述内容变化，也描述发布时间、责任人和回滚入口。

每个数据集对应一份发布版本号 + 一份变更日志，二者缺一不可。

## 数据集版本号：版本格式

采用 `v主.次.修订` 三段式：

- 主版本：词表边界或类别边界变化时升级。
- 次版本：新增批次或场景时升级。
- 修订版本：仅做小修小补或字段修正时升级。

跨数据集不可共享版本号空间，每个数据集独立计数。

## 数据集版本号：变更日志字段

每次发布必须记录：

- `version`：本次版本号。
- `released_at`：发布日期。
- `released_by`：发布负责人。
- `summary`：变更摘要（≤ 200 字）。
- `changes`：具体变更条目列表（每条含范围、影响、是否回滚兼容）。
- `rollback_to`：上一可用版本号。
- `tests_passed`：通过的回归测试 ID 列表。

变更日志使用文本或 Markdown 文件保存，与数据集同目录或在使用方独立保留。

## 数据集版本号：回滚与归档

- 任一回滚必须记录回滚原因与影响范围，不得悄悄替换。
- 被回滚的版本保留在 `archived/dataset-id/<旧版本>/` 至少 12 个月。
- 回滚时可同步撤销所有下游依赖，但需要在发布说明中标注"需同步回滚的下游"。
- 永久归档：达到 12 个月后可压缩归档，但 SHA-256 不删。

## 数据集版本号：发布前自检

发布前必须验证：

- 词表与 RAG 资料 YAML 头中的 `source_refs` 一致。
- 文件 SHA-256 与发布的清单对齐。
- 抽样 5% 切片的标签可重现。
- 至少 1 名独立审核员签字。

任何一项不通过，发布暂停。

## 数据集版本号：常见误区

- 用日期堆叠作为版本号（如 `v20260817`），丢失语义边界。
- 变更日志只写"修复若干问题"，不含具体条目。
- 回滚时连同 SHA-256 一起删除，导致后续无法溯源。
- 不记录责任人，导致回滚决策无人负责。

## 数据集版本号：示例与反例

正例（虚构示例）：版本号 `v2.1.0`，主版本未变；新增"音频方言"批次 200 条；修订版本号仅做字段对齐。

反例：用 `v2026-08-17` 作为版本号，看不出"方言批次首次加入"是主版本还是修订。
