# 教学资料来源核验流程与可追溯性要求

本资料覆盖 BHZD 平台 RAG 资料来源的核验流程、可追溯性要求与冲突处理。读者对象是资料编辑者、教学管理员、来源台账审计员。

## 来源核验：核心定义

来源核验指对每份教学资料引用的来源（标准、教材、企业文档、官方页面、项目内部资料）进行身份、版本、范围与授权的逐项核验，并保留核验证据。

可追溯性要求每条事实都能映射到具体来源条目、章节、版本与核验日期。

## 来源核验：四道关卡

每条来源依次通过：

1. 身份关：来源发布方是否为权威机构（标准机构、大学、企业官网等）。
2. 版本关：来源日期 / 版本是否在资料引用范围内，过期内容需重新核验。
3. 范围关：来源所述内容是否覆盖资料中引用的结论，不能以偏概全。
4. 授权关：来源许可证是否允许 BHZD 的使用范围（教学、内部或公开）。

任一关卡未通过，相关资料退回修改。

## 来源核验：核验证据

核验证据应包括：

- 来源 URL、DOI、ISBN 或本地归档路径。
- 核验日期与核验人。
- 引用到的具体章节、页码或行号。
- 截图或离线快照（限于非涉密内容）。
- 授权许可证原文摘录或审批单编号。

证据按 `BATCH-<日期>-<序号>#<资料ID>@<版本>` 索引。

## 来源核验：冲突处理

两个或多个来源冲突时：

- 优先核对版本、地区、产品版本与定义口径。
- 在正文中分别说明两个结论及各自条件。
- 无法解决时标记"存在来源冲突，待确认"。
- 后续确认权威结论时更新版本，不覆盖旧版本的审计记录。

冲突解决记录在来源台账的 `notes` 字段。

## 来源核验：常见误区

- 仅写来源名称不写 URL / 版本。
- 引用过期标准却未标记版本差异。
- 仅把网站首页可访问当作全文已核验。
- 用 AI 生成的内容冒充来源。

## 来源核验：示例与反例

正例（虚构示例）：引用 ISO 27001:2022，写明"访问 2026-07-12、访问 URL、章节号、核验人姓名"。

反例：仅写"参考 ISO 27001"，未注明版本与具体章节，引用时无法复核。
