# Task 6 教学应用与诊断系统设计规格

**状态：** 已确认；待实施

**批准基线：** 2026-07-14 Task 6 实施简报

## 1. 目标与完成边界

Task 6 交付一个可在 Windows 10/11 最新版 Chrome 或 Edge 中运行的本地 Web 教学应用。应用使用 Tasks 1-5 已建立的课程、图谱、来源和场景数据，完成以下教学闭环：

```text
选择内容域 -> 查看能力图谱 -> 学习已发布单元 -> 完成确定性练习
-> 获得规则反馈 -> 更新掌握度 -> 诊断薄弱能力 -> 生成补强计划
```

应用还必须提供企业任务转化、场景规则切换、结构化标注文件诊断和本地学习状态管理。最终操作手册、赛事 PDF、演示视频和 `submission/` 四目录包属于 Task 7，不在本设计范围内。

Task 6 只有在以下三类证据全部成立后才能标记完成：

1. 应用、单元测试、端到端测试和浏览器冒烟测试通过。
2. 内容及场景获得人工领域专家的真实学生试用放行。
3. 2-3 名人工智能专业师生完成规定试用，并留下真实反馈、修订和复测记录。

在第 2、3 项完成前，系统只能标记为开发预览，不得伪造试用或宣称 Task 6 全部完成。

## 2. 非目标

- 不建设生产型数据标注平台、教师后台、账号系统或服务端数据库。
- 不新增未经审核的课程、三档练习或十题入学测评。
- 不把场景复制成四套独立课程结构。
- 不让截图、自由文本或无法验证的文件改变分数和掌握度。
- 不接入或虚构讯飞星辰账号、知识库、工作流和用户系统；本期只保留适配边界。
- 不使用 LLM 参与确定性评分、诊断、掌握度更新或 PRE 补强计划。
- 不使用 Dijkstra 或“最短路径”叙事代替 PRE 有向无环图上的前置学习计划。

## 3. 技术架构

### 3.1 技术选型

- React、TypeScript、Vite 构建单页应用。
- vis-network 作为唯一图谱可视化库。
- Vitest 与 React Testing Library 执行模块和组件测试。
- Playwright 执行 Chromium 与本机 Edge 端到端测试。
- 浏览器 `localStorage` 保存单一开发预览学习档案。
- 所有课程判定、任务匹配、诊断与路径计算均在浏览器本地执行，不上传用户文件。

### 3.2 分层

```text
React 页面与组件
    |
应用服务：课程 / 图谱 / 练习 / 任务转化 / 诊断 / 学习状态
    |
纯 TypeScript 领域模块：索引 / 判定 / 掌握度 / PRE 计划 / 格式解析
    |
只读数据适配器：课程 JSON / 图谱 JSON / 来源台账 / 场景规则
```

领域模块不得依赖 React 或浏览器 DOM，以便使用固定夹具进行快速单元测试。浏览器存储和文件读取通过端口接口注入，后续可替换为星辰平台适配器。

## 4. 数据消费与发布门槛

应用在构建期从仓库根目录导入以下权威输入：

- `data/curriculum/teaching-units.json`
- `data/graph/annotation-capability-graph.json`
- `data/sources/source-registry.json`
- `data/scenarios/*.json`

课程列表只包含同时满足以下条件的单元：

- `review_status == "published"`
- `student_visible == true`
- 单元 ID 位于 `student_visible_unit_ids`

图谱允许显示完整的开发态结构和每个节点的真实状态，但只有满足上述门槛的 `teaching_unit_refs` 可以打开课程。draft/reviewed 节点必须显示“开发态结构节点”标识，不得伪装为已发布教学内容。

构建和测试必须验证可见索引、课程链接、来源引用、场景基础规则引用和图谱端点完整；任何失败都阻止发布构建。

## 5. 信息架构与界面

应用使用统一外壳，不建立彼此割裂的产品页面：

- 顶栏：产品名称、开发预览标识、当前内容域、当前场景和重置学习档案操作。
- 左侧：vis-network 能力图谱，可搜索、缩放、拖动、按节点类型筛选并高亮当前路径。
- 中部：课程内容、练习、自检、任务卡或诊断报告，是主要工作区。
- 右侧：场景选择、通用/场景掌握度、当前节点关系和推荐下一步。
- 小屏：三栏折叠为可键盘操作的抽屉与标签页，不删除核心功能。

视觉遵循现有“星图导航”基线：深空蓝 `#0B1F3A`、星辉青 `#00C6FF`、导航橙 `#FF8A3D`、掌握绿 `#2EC27E`、错误红 `#E5484D` 和纸白 `#F7F8FA`。必须支持清晰焦点环、合理对比度和 `prefers-reduced-motion`。

主要工作模式为：课程、图谱、任务转化和诊断。模式切换保留当前场景与学习状态。

## 6. 核心模块

### 6.1 课程与内容展示

首页按文本、图像、语音、视频展示已发布课程数量和推荐入口。课程工作区展示学习目标、前置能力、规则与来源、正反例、常见错误、练习、补强资源和关联图谱节点。

来源只显示台账中的真实标题、发布方、URL/引用和核验状态。缺失引用时显示数据错误并阻止练习提交，不生成补写内容。

### 6.2 图谱导航

图谱按 CAP、KNG、TSK、SCN、RES、CERT 类型映射节点形状和颜色，按 PRE、ISA、SUP、REL、INSCN、MAPCERT 展示关系。选择节点后显示：

- 前置与后继能力。
- 关联知识、任务、资源、场景和证书。
- 可打开的已发布教学单元。
- 节点状态、当前掌握度和推荐动作。

默认总览可加载全部 166 个节点；选择节点后切换到一至二跳局部子图，避免标签重叠并提高交互响应。

### 6.3 练习、反馈与掌握度

练习界面使用通用结构化响应编辑器承载当前 19 个教学单元。简单封闭字段呈现选择控件；嵌套对象和数组提供带结构提示的 JSON 编辑器。标准答案在提交前不进入可见 UI。

TypeScript 判定器复现 `scripts/evaluate_exercise.py` 的确定性语义：对象键顺序忽略、数组顺序保留、字符串和数值按课程声明处理，依次匹配诊断规则、允许答案或标准答案。输出必须包含：

- 分数与通过状态。
- 命中的规则引用、能力引用和判定版本。
- 错误类型、明确反馈和补强资源。
- 是否需要人工复核。

站内确定性练习与已验证结构化导出文件可以更新掌握度；截图、自由文本和人工复核状态不能更新。更新公式为：

```text
new = clamp(old + 0.35 * (score - old), 0, 1)
```

轻微、中等、严重诊断错误分别扣减 0.03、0.08、0.15。通用掌握度和 `CAP + SCN` 场景掌握度分别存储，不进行自然衰减。

### 6.4 场景切换

支持通用规则、医疗、智能客服、车载语音助手和内容安全五种上下文。场景只对其声明的数据类型生效，规则按 `base_rule_ref` 和 `override_type` 执行：

- `add`：保留通用规则并增加场景约束。
- `replace`：在当前场景中替代对应通用规则。

切换后，图谱高亮、课程规则差异、任务卡和诊断上下文同步更新。任务文本检测到其他场景关键词时只能显示建议，由用户确认后才切换。

### 6.5 任务转化器

任务转化器采用可解释的确定性匹配：

1. 从任务描述识别数据类型、目标关键词和场景关键词。
2. 匹配 TSK、CAP 和 KNG 节点并记录匹配依据。
3. 沿 SUP/ISA 找到所需能力和知识。
4. 反向收集 PRE 前置能力并拓扑排序。
5. 应用当前场景的已发布覆盖规则。
6. 生成一张或多张按 PRE 排序的学习任务卡。

任务卡包含任务名称、学习目标、岗位、当前场景、能力路径、知识、证书、3-9 个步骤、常见错误、资源和自检清单。缺少数据类型或目标时返回结构化澄清问题，不猜测；无法可靠匹配时返回可选择的候选节点和人工确认提示。

### 6.6 结构化文件诊断

文件诊断在浏览器本地完成，单文件上限 5 MiB：

- 通用 JSON：验证当前教学单元声明的响应结构。
- COCO JSON：验证 images、annotations、categories、ID 引用、类别引用和几何基本合法性。
- VOC XML：验证 annotation/object/name/bndbox，检查坐标顺序和图像边界。
- TextGrid：支持标准 long text format 的 interval tiers，检查区间排序、重叠、边界和标签。

诊断必须先让用户选择内容域或目标教学单元。没有标准答案时只输出结构和可验证规则问题，不判断业务语义正确性。每条问题包含严重度、规则依据、能力节点、补强资源、是否影响掌握度和下一任务。

PNG/JPG 上传只显示“辅助讲解模式”，允许本地预览，但不执行自动诊断、不产生分数、不更新掌握度，并提示上传结构化导出文件。

格式不支持、内容损坏、字段不足、体积超限或无法判定时返回可恢复错误，不丢失当前场景和学习状态。

### 6.7 PRE 补强计划

系统从目标能力反向收集掌握度低于 0.8 或未测评的 PRE 前置节点，在得到的有向无环子图上进行稳定拓扑排序。已掌握节点保留在路径解释中但跳过练习。输出统一称“按前置关系排序的补强计划”，不称可替代意义上的最短路径。

## 7. 状态与隐私

本地档案保存以下版本化数据：

- 通用和场景掌握度。
- 练习尝试、分数、判定版本和时间戳。
- 最近内容域、场景、节点和任务卡。

首期只支持一个匿名本地开发档案。应用提供明确的“重置本地学习数据”操作。上传文件只在当前页面内存中解析，不写入 `localStorage`、不发送网络请求；诊断历史只保存经过最小化的结果摘要，不保存原始文件内容。

## 8. 错误处理

- 数据契约错误：构建或启动失败，并指出文件、引用和字段。
- 课程不可消费：显示状态原因，不提供绕过入口。
- 判定无法分类：标记人工复核，不更新掌握度。
- 图谱关系缺失：显示数据问题并阻止生成伪造路径。
- 浏览器存储损坏或版本过旧：备份可解析字段后迁移；无法迁移时提示用户确认重置。
- 文件解析失败：保留当前页面上下文，给出格式、大小和修复建议。

## 9. 测试与验证

### 9.1 单元与契约测试

- 可见课程过滤及 19 个当前单元索引。
- 图谱 166 节点、240 边和六类关系读取。
- TypeScript 与 Python 判定器对同一标准答案、诊断答案和未分类答案输出一致。
- 掌握度公式、场景隔离、错误扣分和本地状态迁移。
- PRE 反向收集、稳定拓扑排序和循环防御。
- 任务匹配、澄清、场景建议及任务卡字段。
- JSON、COCO JSON、VOC XML、TextGrid 和截图辅助模式。

### 9.2 端到端测试

- 文本、图像、语音、视频各完成一条学习—练习—反馈链。
- 图谱节点选择、关联查看、局部子图和课程跳转。
- 通用与至少两个场景的规则差异。
- 企业任务转化及信息不足时的澄清流程。
- 结构化文件诊断、补强计划和掌握度更新。
- PNG/JPG 不产生诊断、分数或掌握度变化。
- 刷新后学习状态保持，重置后清空。
- 键盘访问、可见焦点、小屏布局和减少动效。

### 9.3 完成命令与人工检查

实施计划必须包含并最终运行：现有 Python 全量测试、图谱与场景验证、前端类型检查、单元测试、生产构建、Playwright Chromium 测试、本机 Edge 冒烟测试以及关键页面视觉检查。

## 10. 试用证据与人工门禁

`evidence/user-trials/` 可先包含试用协议、任务清单、空白记录模板和应用导出的会话摘要格式。任何真实参与者记录必须由实际参与者或组织者提供，不得由开发代理代填。

开展试用前必须记录人工领域专家的身份/角色、审阅范围、结论、日期和剩余风险，并将相应内容与场景条目的 `human_release_allowed` 更新建立在真实证据上。之后由 2-3 名人工智能专业师生完成同一组代表任务，记录角色、完成状态、耗时、错误点、主观反馈、修订决定和复测结果。

如果人工门禁或参与者尚未到位，Task 6 Step 1-2 可以完成并验证，Step 3 保持未完成，最终状态必须明确为“等待真实试用”。

## 12. 已确认决策

- 采用 React + TypeScript + Vite + vis-network 的本地 Web 方案。
- 使用浏览器本地状态，不引入后端或账号系统。
- 确定性功能不依赖 LLM；星辰平台只保留未来适配边界。
- 只使用现有已发布教学单元，不扩张 Tasks 1-5 内容范围。
- 用户将在开发完成后提供人工领域专家放行并协调 2-3 名真实试用者。
