# 标航智导 Agent 平台重构设计

**状态：** 已批准任务简报；待用户复核书面规格

**设计日期：** 2026-07-17

**首期环境：** Windows 10/11、Node.js 22.12+、最新版 Chrome 或 Edge

## 1. 目标与当前基线

当前仓库已经具备可验证的 React 教学应用、166 节点/240 边能力图谱、已发布课程、确定性练习、企业任务转化、结构化文件诊断、场景规则和本地学习状态。现有应用的主要入口仍是课程、图谱、任务和诊断工作区；它能完成教学闭环，但不包含真实 LLM、服务端 Agent 编排、登录用户、模型供应商管理或跨设备会话。

本轮目标是在保留上述确定性能力的前提下，将系统重构为真实 Agent 平台：

1. 用户登录后直接向 Agent 描述学习目标或标注任务。
2. Agent 理解意图、展示简明计划、选择工具并流式返回状态。
3. 课程、图谱、任务转化和标注诊断成为 Agent 可调用的类型化工具。
4. 工具工作区直接嵌入 Agent 对话；用户需要精细操作时进入专注视图。
5. 读取类工具可自动执行；任何改变用户状态的操作必须先确认。
6. 管理员通过未公开链接的 `/admin` 配置多个真实模型供应商、主模型和回退模型。
7. 首期在 Windows 完成开发与真实模型验证；Linux/Docker 和讯飞平台托管部署属于后续阶段。

本规格描述目标态，不表示相关后端、认证、管理界面或 LLM 接入已经完成。

## 2. 范围与非目标

### 2.1 首期范围

- Windows 本地开发和验证。
- React 前端与同源 Node.js/TypeScript 后端。
- SQLite 单实例持久化。
- 邮箱和密码注册、邮箱验证、登录、退出、忘记密码和邮件重置。
- 单一管理员、仅密码登录、独立管理员会话。
- `/admin` 模型供应商配置、连接测试、主模型和单一回退模型。
- 讯飞星辰原生、星火原生、Chat Completions、Anthropic Messages 四类适配器。
- Agent 流式输出、计划状态、工具调用、人工确认和故障回退。
- 登录用户的跨设备会话、学习状态和工具摘要。
- 用户按会话删除历史或清除全部历史。
- Windows 单元、集成、端到端、安全和真实模型冒烟验证。

### 2.2 非目标

- 首期不交付 Linux、Docker、Kubernetes 或多实例部署。
- 首期不把编排托管到讯飞星辰平台；只实现星辰和星火原生接口适配。
- 不建设多管理员、管理员用户名、角色权限矩阵或组织租户。
- 不建设生产型数据标注平台、教师后台或素材管理系统。
- 不让 LLM 直接计算练习分数、文件诊断结果、掌握度或 PRE 路径。
- 不持久化用户上传的原始标注文件。
- 不在前台导航、帮助、站点地图或普通用户页面中提供 `/admin` 入口。
- 不在仓库、数据库或日志中保存明文模型密钥、管理员密码或 SMTP 密码。

## 3. 总体架构

```text
浏览器
├── 普通用户界面
│   ├── 注册、登录、邮箱验证、密码重置
│   └── Agent 指挥舱与嵌入式工具工作区
└── /admin
    └── 单一管理员密码认证与模型供应商配置
            │ 同源 HTTPS / 开发期 Vite 代理
            ▼
Node.js / TypeScript 服务
├── Auth：用户、邮箱令牌、用户会话
├── Admin Auth：管理员密码、独立会话、限流
├── Agent Orchestrator：计划、流式事件、工具编排、确认门
├── Provider Registry：主模型、回退模型、连接测试
├── Provider Adapters
│   ├── Xunfei Xingchen Native
│   ├── Xunfei Spark Native
│   ├── Chat Completions
│   └── Anthropic Messages
├── Tool Gateway
│   ├── Course Tool
│   ├── Graph Tool
│   ├── Task Conversion Tool
│   └── Diagnostics Tool
└── Persistence：SQLite + 加密供应商密钥
            │
            ├── 现有课程、图谱、场景和来源 JSON

```

首期采用同源单体结构。开发时 Vite 运行前端，代理 `/api` 到 Node 服务；生产构建时 Node 服务可直接托管前端静态文件。这样可避免跨域认证复杂度，并为后续 Linux 部署保留同一应用边界。

## 4. 用户认证与会话

### 4.1 注册与登录

- 注册仅收集邮箱和密码。
- 邮箱按小写、去首尾空格后的规范值建立唯一索引。
- 密码使用 Argon2id 哈希；数据库不保存可逆密码。
- 注册后账号处于 `pending_verification`，完成邮件验证后才可使用 Agent。
- 登录成功后签发随机会话令牌；数据库只保存令牌哈希。
- Cookie 必须为 `HttpOnly`、`SameSite=Lax`；生产 HTTPS 环境增加 `Secure`。
- 登录、注册、验证码重发和密码重置同时按 IP 与账号限流。
- 错误信息不暴露邮箱是否已注册；审计记录保留脱敏结果。

### 4.2 邮箱验证与密码重置

- SMTP 参数由部署环境提供，不在普通页面或管理员页面保存。
- 邮箱验证令牌和密码重置令牌均使用高熵随机值；数据库只保存哈希和过期时间。
- 验证令牌仅能使用一次；密码重置成功后撤销该用户全部现有会话。
- 首期可使用现有邮箱提供的免费 SMTP 服务；正式外网部署前重新核验额度、发信域名和送达率。

### 4.3 用户数据

服务端保存：

- 用户账号状态和安全审计摘要。
- Agent 会话标题、消息文本和时间戳。
- Agent 运行、工具调用和确认结果的结构化摘要。
- 通用与场景掌握度、练习记录、任务卡和最小化诊断摘要。

服务端不保存：

- 上传的原始 JSON、XML、TextGrid、图片、音频或视频文件。
- 模型供应商返回的隐藏推理内容。
- 不属于教学记录所需的完整请求头或敏感网络信息。

用户可以删除单条会话或清除全部会话历史。账号删除不在首期范围，但数据结构必须允许后续实现。

## 5. 管理员认证与 `/admin`

### 5.1 入口

- 管理员在浏览器地址栏直接访问 `/admin`。
- 普通用户导航、页脚、帮助、快捷入口和站点地图不提供该链接。
- 未认证时只显示管理员密码输入页，不显示供应商名称、状态或系统配置。
- `/admin` 的隐藏性只减少误触，不作为安全控制。

### 5.2 单一管理员密码

- 系统不提供默认密码。
- 部署前通过 Windows PowerShell 运行密码哈希命令生成 Argon2id 哈希。
- 哈希通过 `BHZD_ADMIN_PASSWORD_HASH` 环境变量注入，不进入 SQLite。
- 管理员使用独立 Cookie 名称和独立会话表，不与普通用户会话共用。
- 登录实施 IP 限流、指数退避和短期失败锁定。
- 所有写操作要求 CSRF 防护；修改主模型、回退模型或密钥前重新验证管理员会话有效性。

### 5.3 管理员界面能力

- 新建、编辑、禁用和删除供应商配置。
- 选择协议类型、显示名称、Base URL、模型名称、API Key 和协议所需参数。
- 保存多个配置；任何时刻最多一个主模型和一个回退模型。
- 发起最小连接测试并显示脱敏结果、延迟、模型标识和错误分类。
- 仅在新建或主动更换时接收完整密钥；后续页面只显示掩码。
- 查看供应商最后测试时间、最近成功时间和脱敏错误摘要。
- 查看供应商配置变更审计记录。

前台普通用户 API 不返回供应商配置、Base URL、密钥掩码、管理员审计或模型测试详情。

## 6. 模型供应商与密钥安全

### 6.1 配置模型

每个供应商配置至少包含：

```text
id
display_name
protocol
base_url
model
encrypted_api_key
encryption_key_version
optional_headers
timeout_ms
max_output_tokens
temperature
enabled
is_primary
is_fallback
last_tested_at
last_test_status
created_at
updated_at
```

`optional_headers` 只允许经过白名单校验的静态请求头；禁止覆盖 `Host`、`Content-Length`、转发头和系统认证头。

### 6.2 加密

- API Key 使用 AES-256-GCM 加密后写入 SQLite。
- 加密主密钥通过 `BHZD_CONFIG_ENCRYPTION_KEY` 环境变量注入。
- 每条密文使用独立随机 nonce，并保存认证标签和密钥版本。
- 日志、异常、API 响应和连接测试结果不得包含完整密钥。
- 缺少主密钥时服务拒绝加载供应商配置，不降级为明文。

### 6.3 四类首期适配器

1. **讯飞星辰原生适配器**：面向星辰 Agent/应用接口，独立处理其会话标识、认证和流式事件。
2. **讯飞星火原生适配器**：面向星火大模型原生接口，独立处理其签名、认证、流式响应和工具能力。
3. **Chat Completions 适配器**：支持兼容 Chat Completions 的 Base URL、模型、流式增量和工具调用。
4. **Anthropic Messages 适配器**：支持 Messages、content blocks、streaming 和 `tool_use`/`tool_result`。

实现阶段必须依据当时有效的官方文档和真实账号权限校验讯飞接口，不从旧示例猜测字段。四类适配器统一映射为内部事件模型：

```text
run.started
plan.updated
message.delta
tool.call.requested
tool.call.started
tool.call.completed
confirmation.required
run.completed
run.failed
```

### 6.4 主模型与回退模型

- 新会话运行优先使用启用状态的主模型。
- 主模型在生成任何可见内容或执行任何写工具前发生网络、限流或供应商错误时，可切换到回退模型。
- 已经产生可见增量时，界面提示中断并询问用户是否使用回退模型继续，避免静默生成重复内容。
- 已执行写工具后禁止自动重放整轮请求；编排器从持久化检查点恢复或要求用户确认。
- 配置错误、认证错误和内容安全拒绝不得无限重试。

## 7. Agent 编排与工具边界

### 7.1 编排流程

```text
用户消息
  -> 身份、额度和输入校验
  -> 主模型理解目标并产生简明计划
  -> 编排器验证工具名称、参数和权限
  -> 读取类工具自动执行
  -> 结果作为嵌入式工作区返回
  -> 写入类工具触发确认门
  -> 用户确认后执行并记录摘要
  -> Agent 解释结果和下一步
```

计划是可观察状态，不要求暴露模型隐藏推理。界面只显示用户可理解的步骤、工具、状态、依据和错误。

### 7.2 类型化工具

| 工具 | 类型 | 默认权限 | 结果 |
|---|---|---|---|
| `course.search` | 读取 | 自动 | 已发布课程、规则、示例和资源卡 |
| `graph.query` | 读取 | 自动 | 局部图谱、PRE 路径、关联节点和依据 |
| `task.preview` | 读取 | 自动 | 尚未保存的任务卡预览 |
| `task.create` | 写入 | 必须确认 | 保存到用户账号的学习任务 |
| `diagnostics.preview` | 读取 | 自动 | 当前请求内的结构化诊断结果 |
| `diagnostics.saveSummary` | 写入 | 必须确认 | 不含原文件的诊断摘要 |
| `learning.previewUpdate` | 读取 | 自动 | 掌握度变化预览与规则依据 |
| `learning.commitUpdate` | 写入 | 必须确认 | 服务端学习状态更新 |

所有工具参数使用显式 schema 校验。模型不能构造任意文件路径、数据库查询、网络地址或未登记工具。

### 7.3 确定性责任边界

LLM 可以：

- 理解目标、提出澄清问题和选择工具。
- 生成面向用户的计划摘要和结果解释。
- 将工具的结构化输出组织为教学对话。

LLM 不可以：

- 自行决定练习正确答案或分数。
- 直接修改掌握度、诊断摘要或已保存任务。
- 绕过课程发布状态、来源、场景规则或 PRE 关系。
- 把截图、自由文本或无法验证的文件写成确定性诊断结论。

## 8. Agent 指挥舱交互

### 8.1 信息架构

批准的交互基线为“弱导航、强 Agent、工具内嵌”：

- 顶部只保留品牌、Agent 状态、当前上下文和用户入口，不展示四个平级主 Tab。
- 左侧展示当前任务、可用 Agent 能力和最近会话；工具是能力状态，不是必须手动选择的页面。
- 中部是 Agent 主对话、简明计划和嵌入式工具工作区。
- 右侧是可折叠执行轨迹、上下文和确认状态。
- 图谱、课程、任务转化和诊断在对话中按需出现；复杂交互可进入专注视图，并能返回原会话。

### 8.2 文字密度

生产界面不得把设计说明直接展示给用户。默认只显示：

- 当前任务。
- 正在执行的步骤和工具。
- 关键结果与依据状态。
- 一个主要下一步操作。

工具参数、详细规则、隐私边界和完整调用记录放入“查看依据”“执行详情”或专注视图。错误提示使用短句，并提供可执行恢复动作。

### 8.3 响应式策略

- 桌面端保留左任务区、中对话区和右轨迹区。
- 窄屏将左侧能力区收为抽屉，将右侧轨迹收为底部面板。
- 嵌入式工作区单列显示，关键确认按钮保持可见。
- 遵循键盘导航、语义焦点、对比度和 `prefers-reduced-motion`。

## 11. 错误处理与可恢复性

- **模型不可用：** 显示供应商错误分类；符合条件时建议使用回退模型。
- **工具参数不合法：** 不执行工具，要求模型修正一次；再次失败则向用户显示简明错误。
- **确认过期：** 不执行写操作，重新生成预览并再次确认。
- **流式连接中断：** 保留已接收内容和运行状态，允许重试或选择回退模型。
- **SQLite 写入失败：** 回滚事务，不把未持久化结果显示为已保存。
- **SMTP 失败：** 注册账号保持待验证状态，允许限流后的重发。
- **管理员配置不可解密：** 禁用该配置并记录审计，不输出密文或主密钥信息。
- **上传文件异常：** 保留会话上下文，清理内存数据并给出格式、大小或字段修复建议。

## 12. Windows 首期运行

首期开发和验收使用 PowerShell：

- Node.js 22.12+。
- 前端与服务端依赖安装、数据库迁移和开发服务启动均提供 PowerShell 可执行命令。
- 本地开发可使用 `.env.local`，但只提交 `.env.example`，不得提交真实秘密。
- Windows 环境必须验证 SQLite、Argon2id、SMTP TLS、流式响应和四类供应商适配器。
- 生产 HTTPS、安全 Cookie、反向代理和 Linux 服务管理属于后续部署任务，但首期代码不得依赖 Windows 专用路径或注册表。

## 13. 测试与验收

### 13.1 自动化测试

- 用户注册、验证、登录、退出、重置和会话撤销。
- 管理员密码、限流、独立会话、CSRF 和未授权 API。
- 供应商密钥加解密、掩码、主/回退唯一性和审计。
- 四类适配器的请求映射、流式事件和工具调用归一化。
- 编排器的读取自动执行、写入确认、过期确认和失败恢复。
- 现有课程、图谱、任务转化、诊断和掌握度回归。
- 对话历史、用户删除和原始上传文件不持久化。
- Agent 指挥舱的键盘、移动端、错误态和嵌入式工作区。

### 13.2 真实服务验证

真实 API 冒烟测试必须由管理员提供合法凭据，并分别记录：

- 连接测试时间和目标模型。
- 一次流式文本响应。
- 一次读取工具调用。
- 一次需要确认的写工具预览，且未确认前没有状态变化。
- 主模型失败后的回退行为。

凭据、完整请求头和敏感响应不得进入测试快照、截图或日志。

### 13.3 完成标准

首期完成必须同时满足：

1. Windows 上注册、邮箱验证、登录和密码重置闭环通过。
2. `/admin` 只能由单一管理员密码会话访问，前台无入口。
3. 多供应商配置加密保存，主模型和一个回退模型可切换。
4. 四类首期协议均通过契约测试；具有凭据的协议完成真实冒烟测试。
5. Agent 能自动调用四项现有能力并嵌入结果。
6. 所有写工具均被确认门阻止，直到用户明确确认。
7. 现有确定性教学、诊断和图谱测试继续通过。
8. 原始上传文件没有写入数据库、日志或会话历史。
9. Windows Chrome/Edge 的桌面和窄屏流程通过。

## 14. 后续阶段

首期 Windows 闭环稳定后，再设计并评审：

- Linux 和 Docker 部署。
- HTTPS 反向代理、自动备份和监控告警。
- 讯飞星辰平台托管或嵌入模式。
- 多实例共享数据库、队列和分布式限流。
- 管理员密钥轮换、多管理员或组织租户。

后续阶段不得在首期未验证的情况下提前写成已完成能力。

## 15. 已确认决策

- 采用“弱导航、强 Agent、工具内嵌”的 Agent 指挥舱。
- 首期接入真实 LLM。
- 首期支持讯飞星辰原生、星火原生、Chat Completions 和 Anthropic Messages。
- 保存多个供应商配置，设置一个主模型和一个回退模型。
- 仅设置单一管理员，管理员只输入密码。
- 管理员入口只通过地址栏 `/admin` 访问，前台不提供链接。
- 普通用户使用邮箱和密码注册登录，并完成邮箱验证和邮件密码重置。
- 首期使用免费 SMTP 能力，正式部署前复核服务限制。
- 首期为 Windows 单实例；Linux 和讯飞平台托管部署后置。
- 保存对话、工具摘要和学习状态，不保存上传原文件。
- 读取工具自动执行，所有改变用户状态的操作必须确认。
