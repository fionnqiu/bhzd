# 系统闭环断点精简整改方案

> 文档状态：已确认，待实施
>
> 决策日期：2026-08-18
>
> 适用范围：学生端、教师端、系统管理端、RAG 资料链路与能力图谱
>
> 核心原则：能删除的不补建，能收缩的不扩展，只保留能够形成真实用户闭环的功能。

## 1. 目标

本方案针对系统体验审查中确认的闭环断点，逐项给出修改、修复或功能收缩方案。目标不是继续增加页面和概念，而是让保留下来的功能满足以下条件：

1. 页面上的承诺与系统实际行为一致。
2. 用户看到的信息能够进入下一步操作，或明确只是说明信息。
3. 同一业务事实只保留一套判断口径。
4. 不重要且没有下游消费的功能直接移除。
5. 后端兼容字段可以暂时保留，但不继续作为活跃业务能力展示。

## 2. 总体决策

| 编号 | 闭环断点 | 处理类型 | 最简决策 |
| --- | --- | --- | --- |
| 1 | 资料授权、发布和召回口径不一致 | 调整 | 资料成功解析并完成索引后自动发布，不再进行授权确认 |
| 2 | 单题评分、任务总分和掌握度不一致 | 修复 | 任务总分只汇总实际单题评分，取消“填写即得分” |
| 3 | 图谱关联知识、资源、任务和证书不可操作 | 删除/收缩 | 学生端只保留能力、前置关系和生成练习 |
| 4 | 教师任务通知指向教师模板任务 | 修复 | 每位学生的通知绑定自己的任务副本 |
| 5 | 资料元数据、来源台账和能力关联没有消费入口 | 删除/收缩 | 来源仅保留名称和链接，台账与关联不再作为活跃功能 |
| 6 | RAG 参数变化不会处理既有资料 | 建设 | 切片类参数保存后自动批量重切片和重索引 |
| 7 | 安全页、告警和 Provider 状态互相矛盾 | 收缩/修复 | 安全页只展示当前运行事实，当前故障覆盖历史成功状态 |
| 8 | 审计日志有数据但来源和筛选不清楚 | 调整 | 保留基础审计，简化筛选并补齐操作者、时区和保留期 |
| 9 | 教师任务要求资料来源但没有绑定路径，学情可能跨班 | 删除/修复 | 删除任务来源前置要求，学情严格按班级过滤 |
| 10 | 预设学习只生成首课却承诺完整路径 | 收缩 | 改为“预设任务/学习推荐”，一次只生成一个任务 |
| 11 | 收藏只有展示，没有可达收藏入口 | 删除 | 删除收藏展示和入口，不建设新收藏流程 |
| 12 | 角色首页、表单校验和遗留文案不一致 | 修复/清理 | 按角色跳转首页，及时清除错误，移除过期文案 |

## 3. 逐项整改方案

### 3.1 资料上传后自动发布

#### 现状

- 管理端资料可能同时显示“已发布、学生可见、授权待确认”。
- 安全页和部分上传文案仍承诺“待确认不得发布”。
- 学生召回、教师选材和管理员发布使用不同的授权判断条件。
- 来源台账状态会进一步影响召回，增加了同一资料在不同页面含义不同的问题。

#### 最简决策

资料只要文件校验通过，并成功完成解析、切片和索引，就自动进入 `published / student` 状态。发布不再依赖授权确认、人工审核或来源台账状态。

“上传后自动发布”不包括以下情况：

- 文件格式不支持。
- 文件解析、切片或索引失败。
- 管理员主动归档的资料。
- 命中现有敏感信息或文件安全校验并被拒绝的资料。

#### 状态处理矩阵

| 对象状态 | 处理结果 | 是否自动发布 |
| --- | --- | --- |
| 新上传且解析、切片、索引成功 | 写入已发布和学生可见 | 是 |
| 新上传处理失败 | 保持失败，展示失败原因和重试入口 | 否 |
| 存量 `indexed/draft/pending` 且索引完整 | 迁移为已发布和学生可见 | 是 |
| 存量 `forbidden` 或已过期 | 迁移为已归档，保留历史原因 | 否 |
| 已归档 | 保持归档 | 否 |

新流程不再创建 `pending` 或 `forbidden` 授权状态。表中的旧状态只用于一次性存量迁移，避免把曾被明确禁止或已经过期的历史资料意外公开。

#### 修改方案

**前端：**

- 上传页删除授权状态、可见范围和发布确认相关说明。
- 资料列表只展示“处理中、已发布、失败、已归档”四类用户状态。
- 资料详情删除“授权状态”和“等待审核后发布”等信息。
- 安全页删除“资料授权强制登记”和“待确认状态不能发布”的静态承诺。
- 删除手动发布入口；保留重新解析、重新切片、重新索引和归档。

**后端：**

- 上传后的流水线固定为“解析 -> 切片 -> 索引 -> 自动发布”。
- 索引成功后原子写入 `status=published`、`visibility=student` 和 `published_at`。
- 学生召回与教师资料查询统一只判断：已发布、未归档、未过期、索引可用。
- `license_status`、`source_ledger_id` 等旧字段第一阶段保留数据库兼容，但不再参与发布、召回或教师选材。
- 批量导入与浏览器上传执行同一自动发布规则，不再保留 `auto_publish=false` 的业务分支。

**存量数据：**

- 将已成功索引、未归档的存量资料统一调整为已发布和学生可见。
- 处理失败或索引不完整的资料保持失败状态，不参与自动迁移。
- 迁移前生成数据库备份，并记录迁移数量与失败清单。

#### 验收标准

- 成功上传的资料无需人工操作即可在学生检索和教师选材中出现。
- 同一资料在管理端、教师端和学生端的可用状态一致。
- 页面和接口中不再出现“待确认不得发布”的承诺。
- 解析或索引失败的资料不会进入学生召回。

#### 规则同步提醒

本决策有意覆盖 `docs/rag-material-preparation-rules.md` 及历史文档变更日志中的“draft / pending / admin 待核验”规则。实施代码修改时必须单独同步这些规则文档，避免新旧政策并存。

### 3.2 统一单题评分、任务总分和掌握度

#### 现状

- 任务题目可以产生确定性或 AI 单题评分。
- 整体提交仍可能使用旧的 `rubric_json` 或“非空答案数量”计算总分。
- “填写了答案”可能被视为正确，并生成掌握度预览。

#### 最简决策

单题评分是唯一评分事实。任务总分只对已完成的单题评分进行加权平均，掌握度只使用该任务总分。

#### 修改方案

- 每道题保存 `score`、`feedback` 和 `graded_at`；主观题等待 AI 评分完成后才能进入任务总分。
- 客观题默认等权；确有必要时使用题目自身权重，不再维护第二套任务 rubric。
- 整体“提交任务”只负责检查题目是否全部提交、汇总单题分数和转换任务状态。
- 删除无 rubric 时的“完整性得分”逻辑；未评分题目不得按已填写计分。
- 掌握度预览、确认写入、教师学情和学生任务详情全部读取同一个任务总分。
- 旧任务没有单题评分时显示“历史任务暂无可靠评分”，不补算虚假成绩。

#### 评分契约

- 单题 `score` 统一使用 `0.0-1.0`，权重必须大于 0，缺省权重为 1。
- 任务总分公式为 `sum(score * weight) / sum(weight)`，最终保留 4 位小数。
- 只有状态为“评分成功”的题目进入公式；存在未评分题目时任务不能生成最终总分。
- AI 评分超时或失败时，题目进入 `grading_failed`，页面提供重试；失败题目不得按完成度计分，也不得生成掌握度。
- 每次整体提交生成唯一 attempt；同一 attempt 的掌握度只能确认写入一次。
- 学生重新作答会生成新 attempt，旧 attempt 和既有掌握度事件保留审计，不在后台静默覆盖。

#### 验收标准

- 页面单题得分的加权结果与任务总分完全一致。
- 空答案、随意填写和未评分答案不会提高掌握度。
- 刷新页面后，学生任务、掌握度和教师学情中的分数一致。

### 3.3 收缩能力图谱为可用能力导航

#### 现状

- 前置能力可以点击，但关联知识、资源、典型任务和证书只是文本标签。
- 证书节点没有来源、课程、进度、报名或获得记录。
- “开始学习”实际创建通用 AI 任务，并不消费图谱返回的典型任务或教学单元。

#### 最简决策

学生端图谱只保留 `CAP` 能力节点和能力之间的前置关系。删除证书展示，不再展示没有可达目标的知识、资源和典型任务。

#### 修改方案

- 图谱画布、搜索和图例只显示能力节点。
- 能力抽屉只保留节点说明、掌握度、前置能力和练习入口。
- “开始学习”改名为“生成练习”，准确反映其行为。
- 删除“关联知识、关联资源、典型任务、相关证书”四个区块。
- 删除学生端证书图例、证书筛选和证书备考分类。
- 后端可以暂时保留 KNOW、RES、TSK、CERT 节点和关系，用于历史兼容；学生接口不再返回这些未消费字段。
- 管理端不新增图谱治理页面；图谱继续作为项目数据文件维护。

#### 验收标准

- 学生看到的每个按钮都有可达结果。
- 学生端不再出现证书或不可点击的关联标签。
- “生成练习”创建的任务名称与页面动作一致，不暗示使用了典型任务。

### 3.4 修复教师任务通知链接

#### 现状

教师发布任务时会为每个学生创建独立任务副本，但通知统一保存教师模板任务 ID。学生点击通知后无法读取该模板任务。

#### 最简决策

通知必须绑定接收学生自己的任务副本 ID。

#### 修改方案

- 创建学生任务副本后，逐学生创建通知并写入对应 `student_task_id`。
- 截止时间变更等后续通知同样使用学生任务副本 ID。
- 旧通知指向无权访问的任务时，前端降级跳转到学习任务列表，不显示 404。
- 保留教师模板任务作为发布源，不允许学生直接访问。

#### 验收标准

- 每位学生点击发布通知都能打开自己的任务。
- 两名学生收到的通知引用不同任务 ID，但均可追溯到同一教师模板。
- 历史失效通知不会进入无权限页或 404 页面。

### 3.5 删除来源台账和资料关联的活跃业务承诺

#### 现状

- 资料详情承诺可后续编辑能力、课程和任务关联，但页面没有编辑入口。
- 来源台账能跳到资料，资料不能反查台账。
- 来源台账与授权状态的复杂治理没有进入教师任务和学生学习主线。

#### 最简决策

资料只保留可读的来源名称和来源链接。来源台账、能力关联、课程关联和任务关联不再作为当前系统的用户功能。

#### 修改方案

- 管理端导航移除“来源台账”。
- 上传页仅保留可选的来源名称和来源链接；不要求选择台账。
- 资料详情删除“关联能力 / 课程 / 任务”卡片及“后续编辑”承诺。
- 资料列表不再根据台账状态显示可用性风险。
- 后端保留现有台账接口和数据库字段一个兼容周期，但新上传资料不再创建或绑定台账。
- 确认没有历史调用方后，再单独规划删除台账表、接口和旧字段；本轮不把删库与行为收缩绑在一起。

#### 验收标准

- 上传资料不需要理解授权、台账或关联模型。
- 资料页面不再承诺系统没有提供的编辑能力。
- 来源台账状态不会影响发布、教师选材或学生召回。

### 3.6 建设 RAG 参数批量自动重处理

#### 现状

- 保存切片参数只更新全局设置，不会处理既有资料。
- 资料详情暗示参数变化会生成新处理版本，但没有批量任务、进度或影响范围。

#### 触发规则

以下参数变化需要自动重处理全部符合资格的资料：

- 切片长度。
- 切片重叠。
- 标题继承。

以下参数保存后立即生效，不触发资料重处理：

- `top_k`。
- 最低相似度阈值。
- temperature、top-p。
- 混合召回、查询改写和重排开关。

嵌入模型或嵌入维度变化不纳入本批处理方案。它需要在独立索引集合中完成全量构建和验证，再执行一次全局原子切换；不得按资料逐个切换并在同一次查询中混用不同模型或维度。

#### 重处理资格矩阵

| 资料状态 | 是否进入批次 | 处理方式 |
| --- | --- | --- |
| 已发布、当前索引可用、未归档、未过期 | 是 | 重切片和重索引，成功后切换版本 |
| 正在首次解析或索引 | 否 | 首次任务固定使用创建时的设置版本；完成后若版本落后，再排入最新批次 |
| 处理失败或当前没有可用索引 | 否 | 继续走资料级失败重试，不进入全局批次 |
| 已归档或已过期 | 否 | 保持原状态 |

首次上传、存量自动发布和参数重处理是三条独立流程。重处理只更新已发布资料的处理版本，绝不把失败、未发布或已归档资料变成已发布。

#### 批量处理流程

1. 管理员保存参数，后端先完成范围校验。
2. 后端生成新的 RAG 设置版本，并计算受影响的未归档资料数量。
3. 为本次设置版本创建唯一批次 ID，复用现有 `rag_jobs` 任务体系批量排队。
4. 每份资料执行“重新切片 -> 重新索引”，不重复解析原文件。
5. 新切片和新索引写入新的 `process_version`，处理期间旧版本继续提供检索。
6. 单份资料全部成功后原子切换当前版本，再清理其旧索引。
7. 单份失败不阻塞其他资料；批次完成后保留失败清单。
8. 管理员可对失败项重试，重试复用原批次和设置版本。

#### 并发与幂等

- 同一资料、同一设置版本只能有一个活动重处理任务。
- 连续保存相同参数不得创建新批次。
- 新参数保存时若上一个批次仍运行，取消尚未开始的旧任务；正在处理的任务完成后不得覆盖更新的设置版本。
- 批次任务不得改变资料的发布或归档状态。
- 设置变更与批次主记录必须在同一事务中创建；批次无法创建时不提交切片参数。
- 新上传任务固定记录创建时的设置版本，避免运行中读取到一半新、一半旧的参数。
- 重处理期间资料被归档时，允许当前工作退出，但禁止切换新版本，并将新产物加入清理队列。
- 服务重启后复用持久化 `rag_jobs` 恢复 queued/running 任务，不依赖内存中的批次状态。
- 旧索引清理失败不回滚已经成功的版本切换；记录 `cleanup_pending` 并异步重试。

#### 页面调整

- 保存前展示“将自动重处理 N 份资料”。
- 保存成功后展示批次 ID、总数、排队中、处理中、成功和失败数量。
- 提供“查看失败项”和“重试失败项”，不建设复杂任务调度控制台。
- 资料详情显示当前处理版本、目标设置版本和最近一次重处理结果。

#### 审计要求

记录以下事件：

- RAG 参数变更前后值。
- 批次 ID、设置版本和影响资料数量。
- 批次开始、完成、失败数量和重试结果。

#### 验收标准

- 修改切片类参数后，全部符合资格的已发布资料自动进入重处理批次。
- 批处理期间学生仍可使用旧索引检索。
- 单份资料成功后才切换到新版本，失败时继续使用旧版本。
- 相同参数重复保存不会重复排队。
- 召回类和生成类参数变化不会错误触发重切片。
- 管理员可以看到准确进度并只重试失败项。
- 批次创建失败时参数不会出现“已保存但没有任务”的中间状态。
- 服务重启、资料中途归档和旧索引清理失败均有可恢复结果。

### 3.7 将安全页改为当前运行状态页

#### 现状

- 页面用静态卡片宣称限流、API Key 加密、授权门禁等能力已启用。
- Provider 页面可能显示历史连接成功，安全页同时显示当前密钥无法解密。
- 告警只有刷新和忽略，无法直接进入修复动作。

#### 最简决策

安全页只展示后端当前能够证明的运行事实，不再承担安全规范说明书或告警工单系统的职责。

#### 修改方案

- 页面名称改为“系统状态”或“运行状态”。
- 删除所有静态“已启用”策略卡片及 PRD/NF 编号。
- 保留当前告警、登录情况、会话数、API 指标和 Provider 指标。
- 指标无样本时显示“暂无数据”，不显示成功或健康结论。
- API Key 解密失败时，Provider 列表当前状态显示“不可用”，历史连接测试作为次要信息保留。
- 解密失败告警提供“前往重新录入密钥”入口；录入并复测成功后自动恢复。
- “忽略”只作为当前管理员隐藏操作，页面明确其不等于问题已解决。

#### 验收标准

- 安全页与 Provider 页面不会同时给出相反的当前状态。
- 每个严重告警都有直接修复入口或明确的处理说明。
- 页面不再展示无法从当前运行状态验证的静态承诺。

### 3.8 简化并校正审计日志

#### 现状

- 操作类型下拉是静态列表，无法覆盖真实出现的动作。
- 操作人主要显示截断 UUID，难以识别。
- 本地时间输入与 UTC 字符串直接比较可能漏数。
- 页面承诺“审计日志不允许删除”，后台又存在保留期清理。

#### 最简决策

保留审计列表、详情和基础筛选，不建设复杂分析平台。页面必须准确说明数据来源与保留期限。

#### 修改方案

- 动作类型由固定下拉改为文本搜索或后端动态枚举。
- 操作人显示名称、角色和短 ID；筛选支持名称、邮箱或完整 ID。
- 前端本地时间统一转换为 UTC 后提交；截止时间按半开区间处理，覆盖所选分钟。
- 系统自动操作显示稳定的系统操作者名称，并在详情中展示批次 ID 或任务 ID。
- 删除“永久不可删除”承诺，改为展示当前保留天数和“用户无法手动删除”。
- 对资料、Provider 和任务等常见目标提供详情深链；不存在的历史目标只显示快照。

#### 验收标准

- 页面能够筛选所有实际存在的动作类型。
- 中国时区选择的时间范围不会偏移或遗漏截止分钟。
- 管理员可以识别操作者，并理解系统操作的触发来源。
- 页面保留期说明与后台清理策略一致。

### 3.9 简化教师任务来源要求并修复学情范围

#### 现状

- AI 生成任务提示发布前补充来源资料，但编辑器没有资料绑定或跳转入口。
- 学生分析中的任务明细可能只按学生 ID 查询，混入其他班级或其他教师的任务。

#### 最简决策

教师任务不再强制绑定 RAG 资料。学情数据必须以教师拥有的班级为边界。

#### 修改方案

- 删除“发布前请补充至少一份来源资料”等提示和发布前置条件。
- 不新增任务与资料绑定模型；任务正文可以保留普通文本参考说明。
- 学生分析查询同时限定 `student_id`、`class_id` 和当前教师可见范围。
- 任务明细只返回当前班级任务；跨班掌握度如需展示，必须明确标记为全局能力数据。
- 学情中的任务标题可跳转到教师可访问的任务模板或班级发布详情。

#### 验收标准

- 教师无需理解资料库治理即可创建和发布任务。
- 某班级的学生任务明细不会混入其他班级任务。
- 学情中的每条任务记录都有可达详情或明确的只读说明。

### 3.10 将预设学习收缩为单任务推荐

#### 现状

- 页面使用“学习路径、岗位路径、证书路径”等名称。
- 启动预设实际只创建第一个单元，系统不保存预设进度，也没有下一课。

#### 最简决策

预设功能改为“预设任务”或“学习推荐”。每次选择只创建一个任务，不建设课程路径和续学状态。

#### 修改方案

- 页面标题改为“学习推荐”。
- “岗位胜任路径、薄弱补强路径”改为“岗位推荐、薄弱能力推荐”。
- 卡片按钮和确认文案统一为“生成任务”。
- 任务标题删除“第1课”，直接使用预设标题和首个单元内容。
- 不持久化 `preset_id`，不展示路径进度、课程总数或下一课。
- 移除证书备考分类；证书类卡片如内容仍有价值，改为普通技能练习名称。

#### 验收标准

- 页面不再承诺路径、课程进度或证书目标。
- 用户每次操作只得到一个与卡片描述一致的任务。
- 预设任务完成后不会出现不存在的“继续下一课”预期。

### 3.11 删除不可达的收藏功能

#### 现状

- 个人中心能够展示收藏列表。
- 原收藏入口所在的独立 RAG 问答页已下线，当前没有正常路径创建收藏。

#### 最简决策

删除收藏功能，不重建入口。

#### 修改方案

- 删除个人中心收藏区块、收藏计数和空状态文案。
- 删除当前路由可达页面中的收藏按钮或相关类型。
- 收藏 API 和数据表先保留一个兼容周期，确认没有调用后再单独删除。
- 历史收藏数据不迁移、不展示，也不影响其他学习数据。

#### 验收标准

- 系统页面中不再出现收藏入口、收藏列表或收藏数量。
- 删除可见功能不会影响任务、会话和资料检索。

### 3.12 清理角色跳转、表单错误和遗留文案

#### 修改方案

**角色首页：**

- 学生访问根路径进入学生工作台。
- 教师访问根路径自动跳转 `/teacher`。
- 系统管理员访问根路径自动跳转 `/admin`；如需验收学生端，通过明确入口进入。

**表单校验：**

- 字段值发生变化时清除该字段的旧错误。
- 再次提交时只展示当前仍存在的错误。
- 优先覆盖教师任务发布中的班级选择、截止时间和必填字段。

**遗留内容：**

- 移除证书路径、证书图例后，同步删除“证书备考”分组逻辑。
- 删除指向已下线检索测试页的说明。
- 旧 `/rag-qa`、`/diagnostics` 等书签重定向可以保留，但不在界面中继续宣传旧功能。

#### 验收标准

- 三种角色从根路径均进入自己的主要工作台。
- 用户修正字段后，过期错误立即消失。
- 页面中不存在已经移除功能的入口、分组或操作说明。

## 4. 建议实施批次

### 批次 A：优先修复真实数据错误

1. 统一单题评分、任务总分和掌握度。
2. 修复教师任务通知 ID。
3. 修复教师学情班级范围。
4. 修复角色首页和表单错误。

### 批次 B：收缩无闭环功能

1. 收缩学生能力图谱并删除证书展示。
2. 删除来源台账和资料关联的用户承诺。
3. 将预设学习改为单任务推荐。
4. 删除收藏功能。
5. 收缩安全页并统一 Provider 当前状态。

### 批次 C：统一资料生命周期

1. 实施上传后自动发布。
2. 迁移存量已索引资料。
3. 统一学生召回和教师选材条件。
4. 同步 RAG 规则文档、页面文案与测试。

### 批次 D：建设批量重处理与审计

1. 建设 RAG 设置版本与批量任务。
2. 实现旧索引保留和原子版本切换。
3. 增加批次进度、失败重试和审计记录。
4. 简化审计筛选并校正时区和保留期。

批次之间应独立提交和验收。批次 D 不应阻塞前三批次对错误行为和无效功能的清理。

## 5. 兼容与删除策略

为降低一次性迁移风险，功能收缩分为两步：

1. **先停用：**删除页面入口和业务判断；写接口返回 `410 Gone`，必要的管理员历史 GET 暂时保留。
2. **再删除：**首个包含停用变更的版本发布满 14 天，且服务端访问日志确认没有外部调用后，通过独立迁移删除字段、接口和死代码。

第一阶段明确保留但停止活跃使用的内容包括：

- `license_status`、`source_ledger_id` 等资料治理字段。
- 来源台账接口和数据表。
- KNOW、RES、TSK、CERT 图谱节点与关系。
- 收藏接口和数据表。
- 旧任务的 rubric、practice 和关联字段。

不得在同一个功能修复中顺带删除这些历史结构；删除应有单独清单、迁移、备份与回归验证。

兼容资产必须逐项记录：端点或字段、允许的读取行为、冻结版本、14 天观测起止时间、调用次数、计划删除版本和恢复备份。若实施审计确认系统没有任何外部调用方，可以在批准后缩短观测期，但不能仅凭“页面没有入口”判断接口无人使用。

## 6. 总体验收口径

全部整改完成后，系统应满足以下结果：

- 上传成功的资料自动发布，学生与教师看到相同的可用事实。
- 题目评分、任务总分、掌握度和教师学情使用同一分数。
- 图谱不展示证书或不可操作关系，每个操作都有真实目标。
- 教师发布通知能打开学生自己的任务。
- RAG 切片参数变化会自动批量重处理既有资料，期间旧索引可用。
- 安全页和 Provider 页面不会给出相互矛盾的当前状态。
- 审计能够说明谁、何时、因何触发了什么动作，并准确说明保留期。
- 教师学情不跨班混入任务。
- 预设、收藏和来源台账不再形成未完成的产品承诺。
- 学生、教师和管理员从根路径进入各自工作台。
