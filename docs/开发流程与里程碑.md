# 标航智导开发流程与里程碑

**适用范围：** 本流程从当前已验证的 React 教学应用出发，建设 Windows 优先的真实 Agent 平台。课程、图谱、任务转化和标注诊断保留为确定性能力，并通过 Agent 工具网关统一编排。

**权威设计：** `docs/superpowers/specs/2026-07-17-agent-platform-design.md`

**权威计划：** `docs/superpowers/plans/2026-07-17-agent-platform-implementation.md`

## 总原则

- 先保护现有教学、图谱和诊断回归基线，再新增服务端、认证和 Agent 编排。
- Agent 负责理解、规划、工具选择和解释；分数、诊断、掌握度与 PRE 路径由确定性工具计算。
- 读取和预览类工具可以自动执行；改变用户状态的操作必须由用户确认。
- 模型密钥、管理员密码和 SMTP 密码不得进入仓库、数据库明文、日志或测试快照。
- 当前态、目标态和真实验证证据必须分开记录，不以设计文档代替已完成实现。
- 首期在 Windows 完成开发与真实模型验证；Linux/Docker 和讯飞平台托管部署后置。

## 当前系统基线

以下能力已经存在，后续任务应复用而不是重做：

- React、TypeScript、Vite 教学应用。
- 文本、图像、语音、视频已发布教学单元。
- 166 节点、240 边能力图谱及 PRE 路径算法。
- 确定性练习、规则反馈和通用/场景掌握度。
- 企业任务转化、场景规则覆盖和学习任务卡。
- JSON、TextGrid、COCO JSON、VOC XML 结构化诊断。
- 本地学习状态、Vitest、pytest 和 Playwright 验证基线。

真实 LLM、用户账号、服务端数据、模型供应商管理和 Agent 编排尚未实现。

## 里程碑

| 里程碑 | 主要工作 | 交付物 | 退出条件 |
|---|---|---|---|
| B0 基线冻结 | 复核当前代码、数据、测试和浏览器行为 | 当前能力清单、回归命令、兼容边界 | 现有自动化与浏览器基线通过，新增工作不重写权威数据 |
| A1 Windows 服务基础 | 建立 Node.js/TypeScript 同源服务、SQLite schema、迁移、配置加载 | `server/`、数据库迁移、PowerShell 启动方式 | Windows 可同时启动前后端，数据库可重建，秘密不入库或日志 |
| A2 用户认证 | 邮箱注册、验证、登录、退出、忘记密码和重置 | Auth API、SMTP、认证页面、用户会话 | 未验证账号不能使用 Agent；会话、限流、令牌失效测试通过 |
| A3 管理员与供应商配置 | 单一管理员 `/admin`、供应商 CRUD、连接测试、主/回退选择、密钥加密 | Admin API/UI、供应商注册表、审计 | 前台无入口；未授权不可读取配置；数据库无明文密钥 |
| A4 模型适配 | 星辰、星火、Chat Completions、Anthropic Messages | 四个适配器、统一流式事件和错误模型 | 契约测试通过；具备凭据的协议完成脱敏真实冒烟 |
| A5 Agent 工具网关 | 将课程、图谱、任务转化、诊断和学习状态封装为类型化工具 | 工具 schema、权限表、确认规则 | 读取工具自动执行；写工具无确认不得改变状态 |
| A6 Agent 编排 | 计划状态、流式对话、工具循环、检查点、回退模型和错误恢复 | Agent API、事件流、确认 API | 工具调用可追踪；中断可恢复；写操作不会重复执行 |
| A7 Agent 指挥舱 | 弱导航、工具内嵌、专注视图、轨迹面板、历史会话 | 用户端 Agent UI、响应式和无障碍状态 | 用户无需先选模块即可完成代表任务；文字密度符合渐进披露原则 |
| A8 质量与真实试用 | 安全、性能、Windows Chrome/Edge、真实模型和师生试用 | 测试报告、脱敏冒烟记录、试用与复测记录 | 无阻断安全或教学问题；真实反馈闭环，不伪造参与者记录 |
| D1 Linux 与生产部署 | Linux/Docker、HTTPS、备份、监控和恢复 | 部署包、运维说明、恢复演练 | Windows 首期稳定后另行评审；生产环境安全检查通过 |
| D2 讯飞平台与赛事交付 | 评估星辰托管/嵌入并整理赛事材料 | 平台验证、运行包、文档、视频、截图 | 只引用真实完成能力；提交包在干净环境通过核验 |

## 开发顺序与依赖

1. B0 通过后才能开始 A1；任何新增服务端工作必须保留现有确定性测试。
2. A1 是 A2-A6 的共同前置。SQLite schema 和秘密加载策略必须先稳定。
3. A2 与 A3 可在 A1 后分别实施，但普通用户会话与管理员会话必须独立。
4. A3 提供供应商注册表后再完成 A4 真实连接；真实凭据只通过管理员界面或环境配置进入运行时。
5. A4 与 A5 共同完成后，A6 才能进行真实工具循环验证。
6. A7 消费 A6 的统一事件模型，不为不同供应商编写四套 UI。
7. A8 通过后再启动 D1；Linux 部署不反向改变首期 Windows 的功能契约。
8. D2 只能引用真实验证结果；讯飞平台托管未验证时只能标为候选路径。

## 技术接口边界

| 接口 | 提供方 -> 使用方 | 最小契约 |
|---|---|---|
| 用户认证 | React -> Auth API | 邮箱、密码、验证/重置令牌；服务端会话 Cookie；通用错误避免账号枚举 |
| 管理员认证 | `/admin` -> Admin Auth | 单一密码、独立会话、CSRF、限流和失败锁定 |
| 模型配置 | Admin UI -> Provider Registry | 协议、Base URL、模型、加密密钥、参数、启用状态、主/回退角色 |
| 模型事件 | Provider Adapter -> Agent Orchestrator | 统一的运行、消息增量、工具调用、确认、完成和失败事件 |
| 工具调用 | Agent Orchestrator -> Tool Gateway | 工具名、版本化 schema、用户/场景上下文、读写权限、幂等键 |
| 图谱数据 | Python 数据脚本 -> Graph Tool | 版本化 JSON、完整引用、PRE 无环、来源和教学单元关联 |
| 课程检索 | 已发布教学数据 -> Course Tool | 仅返回已发布、学生可见、来源可追溯的单元和规则 |
| 文件诊断 | 浏览器/服务端内存 -> Diagnostics Tool | 大小和格式限制、确定性问题列表；原文件不持久化 |
| 学习记录 | 写工具 -> SQLite | 用户、通用/场景掌握度、判定版本、确认记录和时间戳 |
| 邮件 | Auth Service -> SMTP | 验证和密码重置模板；凭据仅来自环境变量 |

## 每轮任务流程

1. 提交任务简报：目标、范围、非目标、拟改文件、验收方式、风险和待确认事项。
2. 取得用户对当前简报的明确确认后，才实施本轮任务。
3. 功能或需求变化时立即停止受影响工作，修订设计、计划、验收和提交文档，再重新确认。
4. 功能开发采用测试先行，并在 Windows 上运行与风险相匹配的单元、集成、E2E 和真实服务验证。
5. 每次项目文档变更追加 `docs/logs/document-changelog.md`；每个 Codex 任务追加外部 Obsidian 工作日志。

## Windows 首期环境

- Node.js 22.12+、Python 和最新版 Chrome/Edge。
- 使用 PowerShell 可直接执行的安装、迁移、启动、测试和密码哈希命令。
- 本地秘密写入未提交的 `.env.local`；仓库只提供无秘密的 `.env.example`。
- 必须验证 SQLite、Argon2id、SMTP TLS、SSE/流式响应和四类供应商适配器在 Windows 上的行为。
- 路径处理使用跨平台 API，不依赖 Windows 注册表或硬编码盘符，为后续 Linux 保留兼容性。

## 内容、隐私与发布策略

- 文本、图像、语音和视频均是正式教学范围；新增 Agent 不得降低教学内容准确性门槛。
- 医疗、客服、车载、内容安全是场景覆盖层，不复制课程主结构。
- LLM 输出不是规范来源；解释必须回链到已发布规则、图谱或确定性工具结果。
- 上传的原始标注文件只在当前请求中解析，不写入 SQLite、日志或会话历史。
- 所有试用、真实模型和平台接入声明必须具有实际参与者、真实凭据或可核验运行证据。
