# 标航智导开发流程与里程碑

**适用范围：** 本流程将标航智导作为数据标注教学智能体建设。文本、图像、语音、视频是课程内容域；行业场景是可扩展的教学规则层。

## 总原则

- 先验证教学内容与练习判定，再开发智能体和视觉表现。
- 图谱必须参与学习顺序、资源关联、任务装配和补强推荐。
- 任何知识条目、案例和练习在进入演示环境前，必须具有可核验来源、适用范围和审阅记录。
- 每个里程碑都须留下可演示结果、验收记录和可提交源文件。

## 里程碑

| 阶段 | 主要工作 | 阶段交付物 | 退出条件 |
|---|---|---|---|
| M0 项目基线 | 确定仓库结构、内容来源台账、素材授权和数据/平台接口边界 | 目录结构、来源台账、接口清单、风险清单 | 每类内容均有来源责任人、可用素材说明和接口责任人 |
| M1 教学内容模型 | 定义教学单元、练习、反馈和能力关系；完成四类内容的最小能力地图 | 教学内容矩阵、数据规范、样例单元 | 每类数据都有可教、可练、可判定的样例 |
| M2 图谱与内容数据 | 建立 CAP/KNG/TSK/SCN/RES/CERT 节点及关系，生成 JSON 与 GraphML | 166 节点、240 边的图谱 v1，校验报告、内容索引 | 图谱无悬空引用、PRE 无环、可定位教学单元 |
| M3 基础教学闭环 | 完成文本与图像的规范讲解、正反例、练习和规则反馈 | 两类基础教学闭环 | 同输入、同数据版本和同判定版本的结果 100% 一致；反馈引用具体规则 |
| M4 语音深度教学 | 建设转写与标点、说话人、语种/方言、情感与副语言、唤醒词/命令词、切割与对齐六项教学链 | 语音课程、音频素材、专项练习 | 六项均有学-练-反馈链，每项至少两类练习；错误可进入诊断与补强 |
| M5 视频扩展 | 在统一模型中增加帧标注、目标追踪、行为事件 | 视频教学单元与练习 | 视频只复用图像的标注原语，不复用其能力节点；视频能力能复用图谱、任务和反馈机制 |
| M6 教学应用与智能体 | 实现课程入口、图谱导航、任务卡、规范解释、学习状态和场景规则覆盖 | 可运行 Web 应用、智能体工作流 | 图谱驱动的教学闭环可完整录屏演示 |
| M7 诊断与个性化 | 接入自检结果、错误定位、掌握度和补强路径 | 诊断报告、学习记录、路径推荐 | 错误能映射到能力节点并给出可执行补强项 |
| M8 质量与试用 | 内容复核、功能回归、无障碍与性能检查、师生试用 | 测试报告、2-3 份试用反馈、修订记录 | 关键流程无阻断问题，反馈已闭环处理 |
| M9 参赛交付 | 整理可运行包、源码、设计文档、PPT、视频与截图 | 四目录提交包、readme、检查表 | 以作品编号为前缀的赛事文件一次归档、无重复、可在目标环境运行 |

## 开发顺序与依赖

1. M0-M2 完成后，才能将内容接入页面或智能体；不允许用模型生成代替未审阅的教学规范。
2. M3 的文本和图像闭环是“教学准确、可判定”的基线。M4 以该基线为前提，完成语音方向的深度实现。
3. M5 不另起一套架构，必须复用教学单元、图谱关系、任务和反馈模型。
4. M6 仅消费经过 M1-M5 校验的数据；场景以规则覆盖形式接入，不复制课程主结构。
5. M7-M9 在功能闭环稳定后进行，避免用演示材料掩盖未验证的教学效果。

## Phase 与里程碑映射

| 主文档阶段 | 对应里程碑 | 阶段目标 |
|---|---|---|
| Phase 1（2026年7月） | M0-M3 | 完成来源、教学模型、166 节点图谱和文本/图像准确教学基线；同时启动语音素材与任务转化原型 |
| Phase 2（2026年8月） | M4-M8 | 完成语音深度教学、视频扩展、教学应用、场景覆盖、诊断路径和师生试用 |

## 技术接口边界

| 接口 | 提供方 -> 使用方 | 最小契约 |
|---|---|---|
| 图谱数据 | Python 数据脚本 -> Web/智能体 | 版本化 JSON，包含节点、边、`source_refs`、`teaching_unit_refs` 和校验摘要 |
| 知识映射 | 知识库 -> 图谱/RAG | `KNG-*` 关联教学概念，`SRC-*` 关联来源；一个 KNG 可关联多个知识条目 |
| 场景覆盖 | 场景配置 -> 任务/讲解/反馈 | 声明 `supported_data_types`、`base_rule_ref`、`override_type` 和覆盖内容 |
| 学习记录 | 练习与诊断 -> 路径推荐 | 存储通用掌握度、场景掌握度、判定版本、错误严重度和时间戳 |
| 平台调用 | Web 应用 -> 星辰 Agent/Python 服务 | 输入任务、当前数据类型、当前场景和图谱上下文；输出结构化讲解、任务卡或澄清问题 |

## 每轮任务流程

1. 提交任务简报：目标、范围、非目标、拟改文件、验收方式、风险与待确认事项。
2. 取得用户对该简报的明确确认后，才实施本轮任务。
3. 编写或修改内容、数据、应用和测试；同步更新受影响的设计、计划、验收或提交文档。
4. 执行与本轮风险匹配的验证，记录结果与遗留风险。
5. 将文档改动追加到 `docs/logs/document-changelog.md`，并按项目规则追加外部 Obsidian 工作日志后再向用户汇报完成情况。

文档变更日志至少记录：日期时间、任务、变更文件、变更原因、验证结果、遗留风险和下次核验条件。实施计划的复选框用于跟踪计划任务状态；日志用于记录实际发生的变更和验证，两者不得互相替代。

## 目标运行环境

验收目标为 Windows 10/11 桌面环境中的最新版 Chrome 或 Edge 浏览器，通过讯飞星辰 Agent 平台的 Web 部署或经批准的本地 Web 启动方式访问。M9 必须分别验证浏览器访问、平台嵌入（如使用）和运行/依赖说明；赛事表单中的平台勾选以当期官方系统选项为准。

## 内容与场景策略

文本、图像、语音、视频均是正式教学范围，不以“优先级低”省略其准确性要求。实现深度的安排为：先稳定文本与图像的准确教学基线，再重点完成语音教学闭环，随后扩展视频。医疗、客服、车载、内容安全只是首批可选案例；新增场景只增加规则、案例和图谱关联。
