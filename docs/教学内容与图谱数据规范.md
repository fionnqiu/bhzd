# 标航智导教学内容与图谱数据规范

## 1. 教学单元规范

每个教学单元对应一个或多个能力节点，必须具备以下字段；缺少任一必填字段的单元不得进入演示环境。

| 字段 | 必填 | 说明 |
|---|---:|---|
| `id` | 是 | 稳定唯一标识，例如 `TU-AUDIO-DATA-BINDING-001`；`CAP-*` 仅表示能力节点 |
| `data_type` | 是 | `text`、`image`、`audio` 或 `video` |
| `title`、`learning_objectives` | 是 | 面向学生可理解的标题与可观察学习目标 |
| `prerequisites` | 是 | 前置能力节点 ID；无前置时使用空数组 |
| `rule_refs` | 是 | `KNG-*` 知识概念 ID；不得只引用模型回答 |
| `source_refs` | 是 | `SRC-*` 来源台账 ID，证明规则、示例和素材的出处 |
| `positive_examples`、`negative_examples` | 是 | 正反例、说明和素材来源 |
| `rule_explanation` | 是 | 区分外部格式事实与本地项目判定策略的规则讲解；本地策略不得表述为外部标准 |
| `exercise` | 是 | 素材、学生操作、答案或判定规则、通过条件 |
| `common_errors`、`remediation` | 是 | 常见错误及补强资源或下一练习 |
| `review_status` | 是 | `draft`、`reviewed`、`published`；仅 `published` 可面向学生 |
| `review_records` | 条件必填 | 草稿可为空；进入 `reviewed` 或 `published` 前须追加完整审阅记录，不得覆盖历史记录 |

统一结构示例：

```json
{
  "id": "TU-AUDIO-DATA-BINDING-001",
  "data_type": "audio",
  "title": "校验音频任务数据绑定",
  "learning_objectives": ["识别 Audio 标签对任务数据字段的引用"],
  "prerequisites": ["CAP-BAS-DATA-FORMAT-001"],
  "rule_refs": ["KNG-AUD-DATA-BINDING-001"],
  "source_refs": ["SRC-LS-AUDIO-TAG-001"],
  "positive_examples": [{"id": "EX-AUDIO-POS-001", "asset_ref": "ASSET-SELF-AUDIO-CONFIG-001", "input": {"value": "$audio"}, "expected": {"valid": true}, "explanation": "引用已存在的 audio 字段", "source_ref": "SRC-LS-AUDIO-TAG-001", "asset_authorization": {"type": "self-authored", "student_use_allowed": true}}],
  "negative_examples": [{"id": "EX-AUDIO-NEG-001", "asset_ref": "ASSET-SELF-AUDIO-CONFIG-002", "input": {"value": "$recording"}, "expected": {"valid": false, "error": "unknown_data_field"}, "explanation": "recording 字段不存在", "source_ref": "SRC-LS-AUDIO-TAG-001", "asset_authorization": {"type": "self-authored", "student_use_allowed": true}}],
  "exercise": {
    "asset_ref": "ASSET-SELF-AUDIO-EXERCISE-001",
    "input": {"task_data_fields": ["audio"], "value": "$audio"},
    "student_action": "判断 value 是否引用存在的数据字段",
    "answer": {"valid": true},
    "evaluation": {"method": "exact_match", "version": "1.0.0"},
    "data_version": "1.0.0",
    "pass_condition": "score == 1.0",
    "capability_refs": ["CAP-AUD-CONFIG-VALIDATE-001"],
    "error_types": ["unknown_data_field"],
    "asset_authorization": {"type": "self-authored", "student_use_allowed": true}
  },
  "common_errors": ["引用不存在的数据字段"],
  "remediation": ["对照任务数据字段表重新核对"],
  "review_status": "draft",
  "student_visible": false
}
```

## 2. 四类教学内容域

| 数据类型 | 最小覆盖能力 | 教学准确性要求 |
|---|---|---|
| 文本 | 分类、实体边界、关系、情感或意图 | 标签体系、边界规则、歧义例与标准答案均可追溯 |
| 图像 | 矩形框、多边形、关键点、分割或属性 | 类别定义、遮挡策略、坐标/掩码判定与导出格式明确 |
| 语音 | 转写、说话人、情感、副语言、切割与对齐 | 时间戳、标签一致性、噪声与口音处理、音频样例均可复核 |
| 视频 | 帧标注、目标追踪、行为事件 | 帧率、抽帧策略、跨帧 ID、事件起止规则和答案明确 |

文本和图像先建立内容准确、例题可判定的基础闭环。语音在相同质量要求上实现最深的教学链。视频复用同一教学结构扩展，不得仅提供概念介绍。

## 3. 图谱规范

核心节点类型固定为：能力 `CAP`、知识 `KNG`、任务 `TSK`、场景 `SCN`、资源 `RES`、证书 `CERT`。图谱 v1 固定为 CAP 40、KNG 60、TSK 20、SCN 4、RES 30、CERT 12，共 166 个节点和 240 条边；后续扩展必须更新版本清单。

`KNG` 是面向教学的知识概念，知识库条目是具体规则、指南或资源文件。初始 62 条知识库条目可通过 `rule_refs` 与 60 个 KNG 建立 `1:N` 关系；`SRC-*` 只用于来源台账，不充当 KNG 节点。

`data/graph/graph-catalog.json` 是图谱分类与关系的单一源目录，`scripts/build_graph.py` 必须由该目录同时、确定性生成 JSON 与 GraphML；两种产物的节点、边和全部序列化属性必须一致，包括描述、状态、来源、教学单元链接、场景支持类型和关系元数据。目录可登记 `draft`、`reviewed` 或 `published` 图谱节点，不依赖教学单元先发布。构建器只为任务节点生成教学单元链接快照；每个快照显式记录 `review_status`、`student_visible` 和 `in_student_visible_index`，仅当三者分别为 `published`、`true`、`true` 时，该链接才标记为 `consumable=true` 并允许教学应用消费。独立验证器必须从图谱顶层 `teaching_units` 路径加载规范教学单元，拒绝未知、重复、缺字段或与规范状态不一致的链接快照，而不能信任图谱中的缓存字段。这一门禁用于解除“先发布教学单元才能建图、先建图才能完成教学单元”的循环依赖。

每个 `TSK` 必须声明 `primary_capability_ref` 和 `primary_knowledge_ref`。两个主引用必须分别解析为 CAP、KNG，并通过入向 `SUP` 边直接支持该任务；所有作为任务支持者的 CAP/KNG，其 `data_types` 必须覆盖任务声明的数据类型。

允许的关系为：

| 关系 | 起点 -> 终点 | 教学用途 |
|---|---|---|
| `PRE` | CAP -> CAP | 决定学习前置顺序，必须无环 |
| `ISA` | 节点 -> 节点 | 表示课程层级或归属 |
| `SUP` | KNG/CAP/RES -> CAP/TSK | 找到规范、资源与任务所需能力 |
| `REL` | 任意教学节点 -> 任意教学节点 | 关联补充内容，不参与前置计算 |
| `INSCN` | CAP/KNG/TSK -> SCN | 挂载场景补充或覆盖规则 |
| `MAPCERT` | CAP -> CERT | 展示证书关联，不替代教学判定 |

通用规则是课程基础层，不创建 `SCN` 节点；首批四个行业场景才创建 SCN 节点。`MAPCERT` 只表示课程能力对照，不代表发证、官方认可或替代正式考核。图谱发布前必须校验：模式与版本正确、六类节点和边数量精确、节点与边 ID 唯一、边端点及关系类型合法、非对象节点或边以结构化模式错误拒绝而非触发运行时异常、`PRE` 无环、所有任务的主 CAP/KNG 引用及支持数据类型正确、已发布或学生可见任务至少有一个声明范围兼容且已核验可发布的知识来源、所有 `INSCN` 关系均有规则元数据，且规则数据类型同时兼容起点节点、目标场景和 `base_rule_ref` 指向的 KNG。JSON 与 GraphML 还必须通过全部序列化属性的结构一致性和重复构建无差异检查。

## 4. 场景扩展规范

场景是规则覆盖层，不是课程分支。每个场景记录 `id`、名称、非空的 `supported_data_types`、适用能力、覆盖规则、案例素材、来源与审阅状态。覆盖规则必须记录 `base_rule_ref`、`override_type`（`replace` 或 `add`）和覆盖内容；规则优先级为已审阅的场景覆盖高于通用规则。

医疗、客服、车载、内容安全可作为首批场景。新增场景时只允许添加 `SCN` 节点、`INSCN` 关系、规则和案例；若需要修改通用能力或知识规则，必须重新审阅受影响的全部教学单元。

场景不要求覆盖全部四类数据类型。一个已发布场景至少须为其声明支持的每种数据类型提供一条已审阅的覆盖规则和一个案例；`INSCN` 只能连接到 `data_types` 与场景支持范围相交的节点，其元数据 `data_types` 还必须是 `base_rule_ref` 对应 KNG 的 `data_types` 子集。

## 5. 掌握度、诊断与补强路径

掌握度分为通用掌握度 `general_mastery` 和按 `CAP + SCN` 保存的场景掌握度 `scenario_mastery`。通用练习仅更新前者，场景练习和场景诊断仅更新后者；缺少场景记录时，该场景显示通用掌握度，不得因一个场景错误降低其他场景的成绩。

分级固定为：`[0, 0.4)` 初学、`[0.4, 0.6)` 待加强、`[0.6, 0.8)` 巩固中、`[0.8, 1]` 已掌握。一次规则判定练习使用 `new = clamp(old + 0.35 * (score - old), 0, 1)` 更新，其中 `score` 为 0 到 1 的确定性判定结果。诊断错误按轻微、中等、严重分别扣减 0.03、0.08、0.15；竞赛版本不使用自然衰减。

十题入学测评只产生文本、图像、语音、视频四个内容域的粗粒度起点，不给具体 CAP 节点赋分；节点掌握度在完成对应练习后首次建立。

补强路径不使用 Dijkstra。系统从目标 CAP 反向收集全部未满足的 `PRE` 前置能力，过滤已掌握节点后，在所得有向无环子图上进行拓扑排序；每个节点显示其规则、练习和资源。`PRE` 是硬前置条件，不允许跳过；已掌握节点从练习队列中跳过但保留在路径说明中。

## 6. 任务转化与输入诊断边界

任务转化器先匹配数据类型、能力和场景。无法匹配时必须要求用户补充数据类型、标注目标或行业情境，不降级为无依据的普通问答。匹配到多个能力时，输出按 `PRE` 顺序排列的多张任务卡；每张卡只服务一个主能力。任务描述出现其他场景关键词时，系统提示“检测到建议场景”并要求用户确认，不自动改变当前场景状态。

正式诊断仅接收可解析的结构化文件：JSON、TextGrid、COCO JSON、VOC XML 及后续经过批准的格式。PNG/JPG 截图只用于辅助讲解，不参与自动评分、掌握度更新或规则结论；截图不清晰、字段缺失或格式不支持时，要求上传结构化导出文件或填写人工复核表单。

## 7. 来源、素材与练习判定

来源台账至少记录：`source_id`、名称、作者或机构、版本或发布日期、原始链接或本地存档、访问日期、许可证或授权、引用位置、核验人、核验日期和状态。图谱来源还须记录 `source_kind`、`supported_claim_types`；跨数据类型来源使用 `supported_data_types`。`usage_rights` 必须分别声明 `citation_allowed` 与 `asset_redistribution_allowed`，公开可访问或可引用不等于允许再分发页面素材、数据集或媒体文件。未经核验的来源只能用于草稿。

来源台账存放于 `data/sources/source-registry.json`。课程按域以 `data/curriculum/<data_type>/teaching-units.json` 为事实源，域文件顶层包含 `schema_version`、`data_type`、`units`，单元按稳定 ID 升序保存。`data/curriculum/teaching-units.json` 是由 `scripts/build_curriculum.py` 确定性生成的中央消费索引，不得作为构建输入，也不得手工维护。Task 3 迁移期的语音、视频草稿显式保存在版本化快照 `data/curriculum/legacy/teaching-units.json`；只有对应域文件缺失时才按域读取快照，Tasks 4-5 建立音频或视频域事实源后由域文件完整覆盖相应回退。构建器拒绝快照或聚合结果中的重复 ID、域类型错配和非规范排序；删除或损坏既有中央输出不得影响重建结果，相同事实源必须生成字节完全一致的中央索引。

来源台账顶层包含 `schema_version`、`sources`。来源 `status` 取值为 `unverified`、`verified`、`restricted`：只有 `verified`、`license_or_authorization.publishable=true` 且 `usage_rights.citation_allowed=true` 的来源可以支撑开发发布声明。项目策略来源还须记录 `publication_scope` 和 `human_release_allowed`；`development_only` 只表示可在独立审阅通过后支撑开发数据，不构成外部权威或真实学生发布授权。`scripts/build_curriculum.py` 对 `reviewed` 和 `published` 单元强制要求 `source_refs` 为非空、无重复、只含非空字符串的列表，并逐项校验来源可解析且满足上述三项资格；同时要求内容摘要、数据版本和判定版本全部匹配批准审阅。Task 3 回退的旧语音、视频草稿可暂时缺少 `review_records`，但进入 `reviewed` 即适用完整门禁。仅 `published` 单元允许 `student_visible=true` 并进入中央可见索引。

每个 KNG 必须记录稳定的 `claim_type` 与 `claim_basis`。`claim_basis=external_reference` 时，每个 `source_ref` 的 `supported_claim_types` 必须包含该 KNG 的 `claim_type`，且来源支持的数据类型覆盖 KNG；仅有可解析的来源 ID 不构成证据。缺少适配来源的概念使用 `claim_basis=curriculum_draft` 且 `source_refs=[]`，不得借用不相关页面。项目自定规则使用 `claim_basis=project_policy`，只能引用 `source_kind=project_policy` 的项目来源，并在展示中明确其不是外部标准或行业权威。

KNG 的 `id`、`label`、`description`、`claim_type`、`claim_basis` 和基础 `source_refs` 构成稳定身份；不得为了挂载单个练习的本地语义而改变既有身份。本地规则以基础 KNG 的 `policy_overlays` 数组增量挂载，每项必须记录唯一 `overlay_id`、本地 `claim_type`、`source_refs`、简明 `description` 和 `version`。覆盖来源必须为 `source_kind=project_policy`，其 `supported_claim_types` 必须包含覆盖声明且数据类型覆盖基础 KNG。覆盖不新增 KNG 节点或图谱边，不改变图谱版本；任务的 `primary_knowledge_ref` 和直接 `SUP` 仍指向意义匹配的基础 KNG，教学单元 `rule_refs` 也只引用基础 KNG ID。

任何 `status=published`、`student_visible=true` 或含有 `consumable=true` 教学链接的 TSK，均须为自身 `primary_knowledge_ref` 以及每个规范教学链接对应单元的全部 `rule_refs` 提供可发布来源。资格可以来自 KNG 的适配基础来源，或来自声明类型、数据类型和项目策略来源均适配且可发布的 `policy_overlays`；同一任务上其他无关 KNG 的合格来源不得替代主知识或必需规则的来源门禁。

Context7 路径与内容证据不等于同标签许可证的直接核验。随后若对精确版本的 raw GitHub 文档与许可证 URL 完成直接 GET，`verification.method` 记录为 `direct_raw_github_http_get`，分别保存文档与许可证 HTTP 状态、响应字节数、许可证文本标记和核验日期，并把 Context7 结果保存在 `prior_context7_evidence`。只有精确文档路径和同标签许可证均成功时才可解除标签风险；否则必须保留 `remaining_license_pin_risk` 和 `publishable=false`。

内容审阅集中登记在 `data/reviews/content-review-registry.json`。每条记录必须包含 `review_id`、`reviewer_id`、`reviewer_type`、`reviewed_commit`、`scope.unit_ids`、`reviewed_at`、逐单元数据与判定版本、`decision`、`findings`、`finding_count`、`remaining_risks` 和 `authorizes_publication`；`reviewed_commit` 必须是 40 位小写十六进制 Git 提交 ID。批准记录的每个 `unit_versions` 项还必须包含 `content_digest`：深拷贝教学单元，仅删除顶层 `review_status`、`student_visible`、`review_records`，再以 UTF-8 对 `json.dumps(..., ensure_ascii=False, sort_keys=True, separators=(',', ':'))` 的结果计算小写 SHA-256 十六进制摘要。`changes_required` 或 `rejected` 记录必须设置 `authorizes_publication=false`；只有内容摘要、数据版本和判定版本全部匹配的 `approved` 记录可以通过开发门禁，AI 批准还必须声明 `independent_of_implementation=true`。AI 审阅不得表述为人工背书；正式赛事或真实学生发布仍须人工领域专家确认。

由 AI 批准并进入 `published` 的教学单元只允许开发发布：批准记录顶层及 `scope` 均须设置 `publication_scope=development_only`、`human_release_allowed=false`；单元 `source_refs` 至少包含一个 `source_kind=project_policy`、`authority_scope=local_project_policy_only` 且具有相同发布边界的来源，所有被引用的项目策略来源也必须满足该边界。发布范围不写入教学单元本身，避免把审阅授权元数据混入内容摘要；开发发布约束由批准审阅和来源资格共同执行。

`rule_refs` 仅保存 `KNG-*` 教学概念，`source_refs` 仅保存 `SRC-*` 来源台账标识，两者不得混用。正例、反例和练习素材均须记录授权；确定性练习须同时给出输入、标准答案、判定方法与版本、通过条件，确保相同输入和判定版本产生一致分数。

练习素材必须标明自制、开源或授权状态；不得使用无法证明授权的真实医疗、客服或个人语音数据。开发候选的标准答案可以由实现代理依据已核验来源和显式项目策略起草，但必须保持 `draft`，并在审阅记录中绑定数据版本和判定版本。Tasks 2-5 的开发发布可按上文经授权的独立 AI 审阅政策执行；正式赛事提交或真实学生使用仍须由人工领域专家确认。歧义样例必须提供允许答案集、部分得分规则和人工复核条件；同一输入、同一数据版本和同一判定版本必须得到 100% 一致的分数。每项练习记录其覆盖的能力节点和错误类型。

通用判定器 `scripts/evaluate_exercise.py` 仅使用 Python 标准库，支持 `exact_match`、`ordered_exact_match` 和 `allowed_answers`。精确比较使用规范 JSON，严格区分布尔值、整数和浮点数；对象忽略键顺序，数组保留顺序。每个允许答案必须显式记录 `answer`、`score`、`manual_review_required`、`error_type`、`feedback` 和非空 `remediation`，不得静默补默认字段。`allowed_answers` 的 `pass_score` 缺省为 `1.0`；显式值必须是 `[0, 1]` 内有限的 JSON 整数或浮点数，布尔值、字符串、空值、NaN 和无穷值均无效。

新候选练习用 `diagnostic_rules` 声明按数组顺序首个命中的确定性诊断，并用 `diagnostic_precedence` 记录顺序；诊断提交不得与标准或允许答案规范重叠。每个声明的错误类型必须能经诊断规则、允许答案或默认反馈到达。结果固定包含分数、通过状态、规则与能力引用、错误、反馈、补强、人工复核标记及数据/判定版本；判定不得读取时间、随机数、网络或进程外状态，相同输入与版本必须生成字节一致的规范 JSON。
