# 标航智导教学内容与图谱数据规范

## 1. 教学单元规范

每个教学单元对应一个或多个能力节点，必须具备以下字段；缺少任一必填字段的单元不得进入演示环境。

| 字段 | 必填 | 说明 |
|---|---:|---|
| `id` | 是 | 稳定唯一标识，例如 `TU-AUDIO-DATA-BINDING-001`；`CAP-*` 仅表示能力节点 |
| `data_type` | 是 | `text`、`image`、`audio` 或 `video` |
| `title`、`learning_objectives` | 是 | 面向学生可理解的标题与可观察学习目标 |
| `prerequisites` | 是 | 前置能力节点 ID；无前置时使用空数组 |
| `rule_refs` | 是 | `KNG-*` 知识概念 ID；不得只引用模型回答 |
| `source_refs` | 是 | `SRC-*` 来源台账 ID，证明规则、示例和素材的出处 |
| `positive_examples`、`negative_examples` | 是 | 正反例、说明和素材来源 |
| `exercise` | 是 | 素材、学生操作、答案或判定规则、通过条件 |
| `common_errors`、`remediation` | 是 | 常见错误及补强资源或下一练习 |
| `review_status` | 是 | `draft`、`reviewed`、`published`；仅 `published` 可面向学生 |

统一结构示例：

```json
{
  "id": "TU-AUDIO-DATA-BINDING-001",
  "data_type": "audio",
  "title": "校验音频任务数据绑定",
  "learning_objectives": ["识别 Audio 标签对任务数据字段的引用"],
  "prerequisites": ["CAP-BAS-DATA-FORMAT-001"],
  "rule_refs": ["KNG-AUD-DATA-BINDING-001"],
  "source_refs": ["SRC-LS-AUDIO-TAG-001"],
  "positive_examples": [{"id": "EX-AUDIO-POS-001", "asset_ref": "ASSET-SELF-AUDIO-CONFIG-001", "input": {"value": "$audio"}, "expected": {"valid": true}, "explanation": "引用已存在的 audio 字段", "source_ref": "SRC-LS-AUDIO-TAG-001", "asset_authorization": {"type": "self-authored", "student_use_allowed": true}}],
  "negative_examples": [{"id": "EX-AUDIO-NEG-001", "asset_ref": "ASSET-SELF-AUDIO-CONFIG-002", "input": {"value": "$recording"}, "expected": {"valid": false, "error": "unknown_data_field"}, "explanation": "recording 字段不存在", "source_ref": "SRC-LS-AUDIO-TAG-001", "asset_authorization": {"type": "self-authored", "student_use_allowed": true}}],
  "exercise": {
    "asset_ref": "ASSET-SELF-AUDIO-EXERCISE-001",
    "input": {"task_data_fields": ["audio"], "value": "$audio"},
    "student_action": "判断 value 是否引用存在的数据字段",
    "answer": {"valid": true},
    "evaluation": {"method": "exact_match", "version": "1.0.0"},
    "data_version": "1.0.0",
    "pass_condition": "score == 1.0",
    "capability_refs": ["CAP-AUD-CONFIG-VALIDATE-001"],
    "error_types": ["unknown_data_field"],
    "asset_authorization": {"type": "self-authored", "student_use_allowed": true}
  },
  "common_errors": ["引用不存在的数据字段"],
  "remediation": ["对照任务数据字段表重新核对"],
  "review_status": "draft",
  "student_visible": false
}
```

## 2. 四类教学内容域

| 数据类型 | 最小覆盖能力 | 教学准确性要求 |
|---|---|---|
| 文本 | 分类、实体边界、关系、情感或意图 | 标签体系、边界规则、歧义例与标准答案均可追溯 |
| 图像 | 矩形框、多边形、关键点、分割或属性 | 类别定义、遮挡策略、坐标/掩码判定与导出格式明确 |
| 语音 | 转写、说话人、情感、副语言、切割与对齐 | 时间戳、标签一致性、噪声与口音处理、音频样例均可复核 |
| 视频 | 帧标注、目标追踪、行为事件 | 帧率、抽帧策略、跨帧 ID、事件起止规则和答案明确 |

文本和图像先建立内容准确、例题可判定的基础闭环。语音在相同质量要求上实现最深的教学链。视频复用同一教学结构扩展，不得仅提供概念介绍。

## 3. 图谱规范

核心节点类型固定为：能力 `CAP`、知识 `KNG`、任务 `TSK`、场景 `SCN`、资源 `RES`、证书 `CERT`。图谱 v1 固定为 CAP 40、KNG 60、TSK 20、SCN 4、RES 30、CERT 12，共 166 个节点和 240 条边；后续扩展必须更新版本清单。

`KNG` 是面向教学的知识概念，知识库条目是具体规则、指南或资源文件。初始 62 条知识库条目可通过 `rule_refs` 与 60 个 KNG 建立 `1:N` 关系；`SRC-*` 只用于来源台账，不充当 KNG 节点。

`data/graph/graph-catalog.json` 是图谱分类与关系的单一源目录，`scripts/build_graph.py` 必须由该目录同时、确定性生成 JSON 与 GraphML；两种产物的节点、边和关键属性必须一致。目录可登记 `draft`、`reviewed` 或 `published` 图谱节点，不依赖教学单元先发布。构建器只为任务节点生成教学单元链接快照；仅当教学单元同时满足 `review_status=published`、`student_visible=true` 且位于 `student_visible_unit_ids` 时，该链接才标记为 `consumable=true` 并允许教学应用消费。这一门禁用于解除“先发布教学单元才能建图、先建图才能完成教学单元”的循环依赖。

允许的关系为：

| 关系 | 起点 -> 终点 | 教学用途 |
|---|---|---|
| `PRE` | CAP -> CAP | 决定学习前置顺序，必须无环 |
| `ISA` | 节点 -> 节点 | 表示课程层级或归属 |
| `SUP` | KNG/CAP/RES -> CAP/TSK | 找到规范、资源与任务所需能力 |
| `REL` | 任意教学节点 -> 任意教学节点 | 关联补充内容，不参与前置计算 |
| `INSCN` | CAP/KNG/TSK -> SCN | 挂载场景补充或覆盖规则 |
| `MAPCERT` | CAP -> CERT | 展示证书关联，不替代教学判定 |

通用规则是课程基础层，不创建 `SCN` 节点；首批四个行业场景才创建 SCN 节点。`MAPCERT` 只表示课程能力对照，不代表发证、官方认可或替代正式考核。图谱发布前必须校验：模式与版本正确、六类节点和边数量精确、节点与边 ID 唯一、边端点及关系类型合法、`PRE` 无环、所有任务可回溯到至少一个能力与一个带可解析来源的知识节点、所有 `INSCN` 关系均有规则元数据且数据类型与场景声明兼容。JSON 与 GraphML 还必须通过结构一致性和重复构建无差异检查。

## 4. 场景扩展规范

场景是规则覆盖层，不是课程分支。每个场景记录 `id`、名称、非空的 `supported_data_types`、适用能力、覆盖规则、案例素材、来源与审阅状态。覆盖规则必须记录 `base_rule_ref`、`override_type`（`replace` 或 `add`）和覆盖内容；规则优先级为已审阅的场景覆盖高于通用规则。

医疗、客服、车载、内容安全可作为首批场景。新增场景时只允许添加 `SCN` 节点、`INSCN` 关系、规则和案例；若需要修改通用能力或知识规则，必须重新审阅受影响的全部教学单元。

场景不要求覆盖全部四类数据类型。一个已发布场景至少须为其声明支持的每种数据类型提供一条已审阅的覆盖规则和一个案例；`INSCN` 只能连接到 `data_types` 与场景支持范围相交的节点。

## 5. 掌握度、诊断与补强路径

掌握度分为通用掌握度 `general_mastery` 和按 `CAP + SCN` 保存的场景掌握度 `scenario_mastery`。通用练习仅更新前者，场景练习和场景诊断仅更新后者；缺少场景记录时，该场景显示通用掌握度，不得因一个场景错误降低其他场景的成绩。

分级固定为：`[0, 0.4)` 初学、`[0.4, 0.6)` 待加强、`[0.6, 0.8)` 巩固中、`[0.8, 1]` 已掌握。一次规则判定练习使用 `new = clamp(old + 0.35 * (score - old), 0, 1)` 更新，其中 `score` 为 0 到 1 的确定性判定结果。诊断错误按轻微、中等、严重分别扣减 0.03、0.08、0.15；竞赛版本不使用自然衰减。

十题入学测评只产生文本、图像、语音、视频四个内容域的粗粒度起点，不给具体 CAP 节点赋分；节点掌握度在完成对应练习后首次建立。

补强路径不使用 Dijkstra。系统从目标 CAP 反向收集全部未满足的 `PRE` 前置能力，过滤已掌握节点后，在所得有向无环子图上进行拓扑排序；每个节点显示其规则、练习和资源。`PRE` 是硬前置条件，不允许跳过；已掌握节点从练习队列中跳过但保留在路径说明中。

## 6. 任务转化与输入诊断边界

任务转化器先匹配数据类型、能力和场景。无法匹配时必须要求用户补充数据类型、标注目标或行业情境，不降级为无依据的普通问答。匹配到多个能力时，输出按 `PRE` 顺序排列的多张任务卡；每张卡只服务一个主能力。任务描述出现其他场景关键词时，系统提示“检测到建议场景”并要求用户确认，不自动改变当前场景状态。

正式诊断仅接收可解析的结构化文件：JSON、TextGrid、COCO JSON、VOC XML 及后续经过批准的格式。PNG/JPG 截图只用于辅助讲解，不参与自动评分、掌握度更新或规则结论；截图不清晰、字段缺失或格式不支持时，要求上传结构化导出文件或填写人工复核表单。

## 7. 来源、素材与练习判定

来源台账至少记录：`source_id`、名称、作者或机构、版本或发布日期、原始链接或本地存档、访问日期、许可证或授权、引用位置、核验人、核验日期和状态。未经核验的来源只能用于草稿。

基线数据分别存放于 `data/sources/source-registry.json` 和 `data/curriculum/teaching-units.json`。来源台账顶层包含 `schema_version`、`sources`；教学单元文件顶层包含 `schema_version`、`student_visible_unit_ids`、`units`。来源 `status` 取值为 `unverified`、`verified`、`restricted`：只有 `verified` 且 `license_or_authorization.publishable=true` 的来源可以被可发布单元引用，`restricted` 条目必须保留授权说明但不得进入学生可见索引。教学单元 `review_status` 取值为 `draft`、`reviewed`、`published`，仅 `published` 单元允许 `student_visible=true` 并出现在 `student_visible_unit_ids`。

每次内容审阅必须记录 `reviewer_id`、`reviewer_type`（`human` 或 `ai_agent`）、`scope`、`reviewed_at`、数据版本、判定版本、`decision`、`findings` 和 `remaining_risks`。经项目所有者明确授权，未参与对应内容实现的独立 AI 审阅代理可批准 Tasks 2-5 的开发数据发布；该记录必须明确标记 `reviewer_type=ai_agent`，不得表述为教师、专家、人工签名或任何人工背书。面向正式赛事提交或真实学生使用的最终发布仍须在 Tasks 6-9 由人工领域专家确认，开发阶段的 AI 审阅不能替代该门槛。

`rule_refs` 仅保存 `KNG-*` 教学概念，`source_refs` 仅保存 `SRC-*` 来源台账标识，两者不得混用。正例、反例和练习素材均须记录授权；确定性练习须同时给出输入、标准答案、判定方法与版本、通过条件，确保相同输入和判定版本产生一致分数。

练习素材必须标明自制、开源或授权状态；不得使用无法证明授权的真实医疗、客服或个人语音数据。标准答案由标注领域专家或授课教师基于已核验来源确认，并记录审阅人和版本。歧义样例必须提供允许答案集、部分得分规则和人工复核条件；同一输入、同一数据版本和同一判定版本必须得到 100% 一致的分数。每项练习记录其覆盖的能力节点和错误类型。
