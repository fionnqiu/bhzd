## 1. 产品定位

### 1.1 一句话定位

标航智导是一款面向高职人工智能技术应用专业、AI 数据标注工程师岗位的教学实训智能体平台，通过“岗位能力图谱 + RAG 知识召回 + 确定性诊断工具”帮助学生完成数据标注能力学习、岗位任务训练、错误诊断和个性化补强。

### 1.2 核心差异

| 维度 | 传统课程 / 标注工具 | 标航智导 |
|------|---------------------|----------|
| 学习入口 | 学生按课程目录查找内容 | 学生说目标，Agent 推荐路径，同时提供预设学习入口 |
| 内容组织 | 文档、视频、练习分散 | 课程、规范、案例、图谱、岗位任务统一关联 |
| 知识来源 | 靠教师手工维护材料 | RAG 管理系统支持资料上传、解析、切片、审核、召回 |
| 能力定位 | 只看分数或完成情况 | 能力图谱显示通用掌握度与场景掌握度 |
| 反馈方式 | 人工批改或泛化建议 | 确定性规则诊断 + 证据引用 + 补强路径 |
| 岗课衔接 | 企业任务难以课堂化 | 岗位任务自动转化为学习任务卡 |

### 1.3 赛事对齐

本产品选择的专业群方向为“人工智能技术应用”，典型岗位为“AI 数据标注工程师”。产品覆盖比赛要求中的三个重点场景：

| 比赛场景 | 产品对应能力 |
|----------|--------------|
| 挖掘岗位能力生成岗位能力图谱 | 数据标注能力图谱、能力路径、证书映射 |
| 岗位典型工作任务转化成学习型任务 | 企业任务转学习任务卡、教师发布任务 |
| 个性化自适应学习 | 入学测评、掌握度模型、诊断补强、个性化推荐 |

## 2. 产品目标

### 2.1 业务目标

| 编号 | 目标 | 衡量方式 |
|------|------|----------|

| BG2 | 降低学生学习入口复杂度 | 首次任务创建转化率、目标输入成功率 |

### 2.2 首期成功指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| 目标识别成功率 | Agent 正确理解学生学习目标并进入合适流程的比例 | >= 85% |

| 诊断摘要保存率 | 学生查看诊断后确认保存摘要的比例 | >= 60% |
| 补强计划完成率 | 学生按 PRE 路径完成补强练习的比例 | >= 50% |
| 教师任务发布成功率 | 教师生成任务卡后发布给班级的比例 | >= 50% |

## 3. 用户角色

### 3.1 学生

主要使用者。目标是完成数据标注学习、岗位任务训练、诊断纠错和考证准备。

核心诉求：

- 不知道从哪里开始时，希望系统给出预设学习路径。
- 有明确目标时，希望直接说目标并获得任务。
- 做错后希望知道错在哪里、依据是什么、下一步练什么。
- 希望看到自己的能力地图和成长轨迹。

### 3.2 教师

教学组织者。目标是把企业任务转化为课堂任务，查看学生学习状态，沉淀教学资源。

核心诉求：

- 快速生成标准化学习任务。
- 发布任务给班级。
- 查看学生薄弱能力。
- 审核课程资料和知识库内容。

### 3.3 内容管理员 / 教研管理员

负责 RAG 资料、规范、课程、案例和来源台账的维护。

核心诉求：

- 上传真实教材、规范、案例、任务文件。
- 查看解析、切片、向量化状态。
- 审核资料后发布到学生可用知识库。
- 测试某个问题能否正确召回资料。

### 3.4 系统管理员

负责模型供应商、密钥、安全、审计和系统配置。

核心诉求：

- 配置讯飞星辰、讯飞星火和其他兼容模型。
- 配置嵌入模型、重排模型、主模型和回退模型。
- 管理 API Key 和访问权限。
- 查看调用日志、错误日志和审计记录。

## 5. 核心产品原则

### 5.1 弱导航，强目标

学生端不强制学生理解系统模块。默认首页是 Agent 指挥舱，但页面必须提供“预设学习”入口，避免学生不知道该问什么。

### 5.2 Agent 不等于唯一入口

Agent 是统一解释和串联入口，但不替代结构化学习。学生应能从以下入口开始：

- 直接说目标。
- 点击预设学习卡。
- 从能力图谱选择薄弱能力。
- 从教师发布任务进入。
- 上传标注文件请求诊断。
- 输入专业问题进行 RAG 问答。

### 5.3 RAG 召回必须可治理

所有专业性回答必须有可追溯资料来源。知识库不只是文件上传功能，而是一整套“上传 - 解析 - 切片 - 审核 - 发布 - 召回 - 评测 - 版本管理”系统。

### 5.4 确定性优先

评分、掌握度、前置路径、诊断扣分、任务保存等关键行为由确定性工具完成；LLM 负责理解、转述、组织和解释。

### 5.5 写操作必须确认

创建学习任务、保存诊断摘要、更新掌握度、发布资料、删除资料、发布班级任务等写操作必须经过确认。

## 7. 学生端页面设计

## 7.1 Agent 指挥舱

### 7.1.1 页面定位

Agent 指挥舱是学生默认首页，用于承接“直接说目标”和“从预设入口开始学习”两类行为。页面不能只有一个空输入框，否则初学者容易不知道该问什么。

### 7.1.2 页面结构

```text
Agent 指挥舱
├── 顶部栏
│   ├── 产品名称
│   ├── 当前场景选择器
│   ├── 当前模型状态
│   └── 用户入口
├── 左侧任务栏
│   ├── 今日推荐
│   ├── 正在学习
│   ├── 教师发布任务
│   └── 最近会话
├── 中部对话区
│   ├── 欢迎态 / 目标输入
│   ├── 预设学习快捷卡
│   ├── 对话流
│   ├── Agent 计划
│   └── 嵌入式工具结果
├── 右侧状态栏
│   ├── 执行轨迹
│   ├── 引用来源
│   ├── 确认门
│   └── 当前能力定位
└── 底部输入区
    ├── 文本输入
    ├── 文件上传
    ├── 快捷指令
    └── 发送按钮
```

### 7.1.3 欢迎态设计

欢迎态应提供四类明确入口：

| 区域 | 内容 |
|------|------|
| 目标输入 | “说说你想学什么，比如：我想学客服语音情感标注” |
| 预设学习 | 文本标注、图像标注、语音标注、视频标注四个入口 |
| 场景入口 | 医疗、智能客服、车载语音助手、内容安全 |
| 常用任务 | 任务转化、标注诊断、考证备考、薄弱补强 |

### 7.1.4 预设学习快捷卡

| 卡片 | 点击后行为 |
|------|------------|
| 文本标注入门 | 进入预设学习流程，默认推荐 NER、文本分类、情感标注 |
| 图像标注入门 | 推荐目标检测、框选规范、COCO/VOC 格式 |
| 语音标注入门 | 推荐语音转写、说话人分离、情感/副语言标注 |
| 视频标注入门 | 推荐时间片段、目标跟踪、动作事件标注 |
| 岗位任务训练 | 弹出任务描述输入模板 |
| 上传结果诊断 | 打开文件上传面板 |
| 考证路径 | 展示 1+X 证书能力路径 |
| 今日薄弱补强 | 根据掌握度推荐一个最优任务 |

### 7.1.5 核心交互

#### 交互 A：学生直接说目标

```text
学生输入目标
  ↓
Agent 识别数据类型、场景、能力
  ↓
若信息不足，只追问一个关键问题
  ↓
展示简明计划
  ↓
调用 RAG、图谱、课程检索工具
  ↓
返回学习建议或任务卡预览
  ↓
学生确认后创建任务
```

#### 交互 B：学生点击预设学习

```text
学生点击“语音标注入门”
  ↓
系统展示预设学习路径
  ↓
Agent 询问是否按默认路径开始
  ↓
学生确认
  ↓
生成第一个学习任务
  ↓
进入任务详情或继续对话
```

#### 交互 C：学生上传文件诊断

```text
学生上传 JSON / TextGrid / COCO JSON / VOC XML
  ↓
系统校验格式
  ↓
诊断工具解析并输出问题
  ↓
RAG 召回规范依据
  ↓
图谱定位薄弱能力
  ↓
Agent 生成补强计划
  ↓
学生确认保存诊断摘要与掌握度更新
```

### 7.1.6 页面状态

| 状态 | 表现 |
|------|------|
| 空白态 | 显示目标输入、预设学习卡和示例问题 |
| 计划中 | 展示 Agent 计划卡 |
| 工具调用中 | 执行轨迹中显示工具名、状态、耗时 |
| 等待确认 | 右侧确认门高亮，主区域展示预览 |
| 已完成 | 展示结果摘要、下一步建议 |
| 失败 | 告知原因和可操作下一步，不暴露技术堆栈 |

### 7.1.7 验收标准

- 学生无需进入其他页面，即可完成一次“目标输入 - 任务生成 - 确认创建”的闭环。
- 欢迎态必须显示不少于 6 个预设入口。
- Agent 专业性回答必须展示引用来源。
- 创建任务、保存诊断、更新掌握度必须出现确认门。
- 执行轨迹至少展示工具名、状态、耗时和是否写操作。

## 7.2 预设学习页面

### 7.2.1 页面定位

解决“学生不知道该问什么”的问题。预设学习不是传统课程目录，而是围绕岗位能力、数据类型、行业场景和证书目标组织的学习入口。

### 7.2.2 页面结构

```text
预设学习
├── 顶部筛选
│   ├── 数据类型：文本 / 图像 / 语音 / 视频
│   ├── 行业场景：通用 / 医疗 / 客服 / 车载 / 内容安全
│   ├── 学习目标：入门 / 专项 / 考证 / 岗位任务
│   └── 难度：1-5
├── 推荐路径区
│   ├── 新手路径
│   ├── 岗位胜任路径
│   ├── 证书备考路径
│   └── 薄弱补强路径
├── 学习单元列表
│   ├── 微课
│   ├── 规范讲解
│   ├── 案例练习
│   └── 模拟任务
└── 右侧说明
    ├── 当前路径能力图谱
    ├── 预计时长
    └── 开始学习按钮
```

### 7.2.3 预设路径

| 路径 | 适用人群 | 内容 |
|------|----------|------|
| 数据标注零基础入门 | 初学学生 | 数据类型认知、标注格式、质量标准 |
| AI 数据标注工程师岗位胜任 | 岗位训练 | 工作流程、常见工具、质检规范 |
| 1+X 数据标注考证路径 | 考证学生 | 证书考点、模拟题、专项练习 |
| 客服语音标注专项 | 场景训练 | 语音转写、情感、副语言、说话人 |
| 车载唤醒词标注专项 | 场景训练 | 唤醒词边界、噪声、正负例 |
| 图像检测标注专项 | 图像方向 | 框选规范、IOU、COCO/VOC 导出 |

### 7.2.4 验收标准

- 学生可在 3 次点击内从预设学习开始一个任务。
- 每条预设路径必须关联至少 1 个能力节点、1 个知识节点、1 个资源和 1 个练习。
- 已掌握能力默认折叠，薄弱能力优先展示。

## 7.3 能力图谱页面

### 7.3.1 页面定位

帮助学生理解“要胜任 AI 数据标注工程师，需要掌握什么”，并把个人掌握度可视化。

### 7.3.2 页面结构

```text
能力图谱
├── 顶部工具栏
│   ├── 搜索能力 / 知识 / 任务
│   ├── 数据类型筛选
│   ├── 场景筛选
│   └── 视图模式：全图 / 局部 / 路径
├── 主图谱区
│   ├── 能力节点
```

## 9. RAG 知识库管理系统

## 9.1 模块定位

RAG 知识库管理系统是标航智导的专业内容底座。它负责把真实教学资料、行业规范、教材片段、案例、任务文件、证书标准等转化为可召回、可引用、可审核、可评测的知识资产。

## 9.2 支持资料类型

| 类型 | 示例 | 首期支持 |
|------|------|----------|
| PDF | 教材、行业规范、比赛方案、证书标准 | P0 |
| Word | 教案、实训指导书、校本教材 | P0 |
| Markdown | 课程讲义、规范整理 | P0 |
| Excel / CSV | 岗位能力表、评分规则、题库 | P1 |
| 图片 | 流程图、标注示例截图 | P1 |
| 音视频转写文本 | 课堂录制、实训讲解 | P2 |
| 网页链接 | 公开规范页面 | P2 |

```text
    ├── 元数据
    ├── 关联能力
```

### 9.3.2 资料状态

| 状态 | 说明 |
|------|------|

### 9.10.3 核心指标

## 21. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| RAG 资料不足 | 回答缺少依据 | 优先上传教材、规范、案例和任务模板 |
| 切片质量差 | 召回不准 | 提供切片编辑器和召回测试台 |
| LLM 编造答案 | 专业可信度下降 | 强制引用来源，无召回时拒答 |
| 页面入口过多 | 学生迷路 | 学生端默认只突出 Agent 输入和预设学习 |
| Agent 过于发散 | 无法完成学习闭环 | 使用预设流程、工具计划和确认门约束 |
| 教师端开发量大 | 影响首期交付 | MVP 优先教师任务发布和资料审核 |
| 模型供应商不稳定 | 演示失败 | 配置主 / 回退模型和离线演示数据 |

## 24. 附录：研发拆解建议

### 24.1 第一开发闭环：学生可用闭环

目标：让学生不用理解复杂模块，也能完成一次学习。

| 顺序 | 交付项 | 依赖 |
|------|--------|------|
| 1 | 登录 / 注册 / 基础用户态 | 无 |
| 2 | Agent 指挥舱欢迎态与输入框 | 用户态 |
| 3 | 预设学习卡与预设路径数据 | 教学单元 |
| 4 | 学习任务卡预览与创建 | 确认门 |
| 5 | 学习任务详情与完成反馈 | 掌握度模型 |
| 6 | 能力图谱局部展示 | 图谱数据 |

### 24.2 第二开发闭环：RAG 可召回闭环

目标：让系统接入真实教学资料，并能在学生端生成带引用答案。

| 顺序 | 交付项 | 依赖 |
|------|--------|------|
| 1 | RAG 资料上传与元数据表单 | 文件存储 |
| 2 | 文档解析与切片任务 | 解析器 |
| 3 | 向量化与索引 | 嵌入模型 |
| 4 | 资料审核与发布 | 权限系统 |
| 5 | 召回测试台 | rag.search |
| 6 | 学生端 RAG 问答与引用展示 | rag.answer |

### 24.3 第三开发闭环：诊断补强闭环

目标：让学生提交真实标注结果后获得规则诊断和补强路径。

| 顺序 | 交付项 | 依赖 |
|------|--------|------|
| 1 | 标注文件上传与格式校验 | 文件解析器 |
| 2 | 确定性诊断规则 | 场景规则库 |
| 3 | RAG 召回规则依据 | 已发布知识库 |
| 4 | 图谱定位薄弱能力 | 能力图谱 |
| 5 | 补强计划生成 | PRE 路径 |
| 6 | 保存诊断摘要与掌握度更新 | 确认门 |

### 24.4 第四开发闭环：教师教学闭环

目标：让教师能把岗位任务转成课堂任务并发布给学生。

| 顺序 | 交付项 | 依赖 |
|------|--------|------|
| 1 | 教师工作台 | 教师角色 |
| 2 | 教学任务生成 | Agent + RAG + 图谱 |
| 3 | 教师编辑任务卡 | 任务模型 |
| 4 | 班级发布 | 班级模型 |
| 5 | 学生接收任务 | 学生任务列表 |
| 6 | 学情分析基础报表 | 学习行为数据 |
